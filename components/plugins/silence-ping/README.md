# 主动私信（silence-ping v1.6.0）

> **v1.6.0 核心升级（根治「主宾颠倒 / 分不清哪句话是谁说的」）**：
> 1. **引用头剥离与转译（`cleanMessageForPrompt`）**：自动剥离 `[引用 某人：长文]`，转译为简短的 `（回应「…」）`，防止 80 字截断后只剩被引用的机器人原话、导致模型把自己的经历安到对方头上。
> 2. **双向箭头强锚定 + 连续短句归并（`groupRecentTurns`）**：废除易与正文“我/你”发生代词碰撞的裸 `我：` / `对方：`，改为 `[#轮次｜时间] 【对方(昵称) → 对你说】` 与 `【你(botName) → 对Ta说】`，并将同一人 3 分钟内连发的短句合并为一轮。
> 3. **双方最后表态对账单（`buildSpeakerLedger`）**：由纯 JS 分别提取「对方最后对你说的话」与「你最后对对方说的话」并列对账，显式标明处境归属与当前停顿方。
> 4. **System/User 分离 + JSON 微推理顺序 + 2-gram 防复读硬闸**：在 `thinkingMode: 'off'` 下强制模型按 `lastState`（15 字主宾确认）→ `mind` → `say` 的顺序输出，并在发送前用 2-gram 比对最近 4 条消息，拦截自我复读或学舌。


> 目录 id 是 `silence-ping`，类型是**确定性型插件**（`plugins/`），能力名 `status.silence-ping`。

**让机器人学会「先开口」。**

默认情况下，机器人只会在别人说话之后才回复——它没有"想起你"这个能力。这个插件补上另一半：**每隔一段时间自己醒一次，判断现在方不方便说话；方便的话，就翻出你们最近的真实聊天记录交给 AI，问一句「现在该不该开口、开口说什么」。** AI 说要，就把这句话作为私信发出去；AI 说不要，就什么都不做。

适合「想让机器人偶尔主动关心一下熟人，但不想它变成话痨」的场景。

---

## 它是怎么工作的

一次「醒来」走完这七步：

```
1. 隔一会儿醒一次（默认 15~30 分钟随机，不像打卡）
2. 先看现在能不能发 —— 总开关 / 睡眠时段 / 上班时段 / 当天额度 / 对方刚回过话
   ↑ 全部是本地规则，一步都不花 token
3. 能发的话，翻出这个人最近的私信记录（默认最近 12 条），
   再看「上次它主动说了什么、对方回了没」
4. 把这些交给 AI，问：现在要不要主动说句话？说什么？
5. AI 说不要 → 什么都不做；说好 → 把这句作为私信发出去
6. 记下时间、内容、对方回没回（下次判断要用）
7. 继续睡，等下一次醒来
```

> ⚠️ **只发私信。** 群聊消息不读、不触发、不回复、也不主动发。群聊的主动开口由核心自己的机制负责，与本插件无关。

## 六个关键特性

| 特性 | 说明 |
|---|---|
| **省 token** | 醒来的绝大多数时候不需要调用 AI：本地规则先筛一遍，只有真的可能开口时才问一次。全局还共享一份判断，不会对每个人各问一次。 |
| **没回就不再追** | 对方没回你主动发的那条，就把他挂起，**直到他先开口**才重新考虑。这不是按时间恢复，所以"发了一句没人理"不会变成三番五次追问。 |
| **防重复** | 两道本地保险：① 查插件自己的记录；② 直接查聊天记录里最近有没有机器人发言（**包括别的插件发的**）。防止"插件重载后记忆清零 → 一分钟内给同一人连发两条"。 |
| **两个勿扰时段** | **睡眠时间**（默认每天 00:00-07:00）和**上班时段**（默认工作日 09:00-12:00 与 14:00-18:00）。上班那个可以一键关掉。 |
| **可以只盯指定的人** | 留空 = 白名单里所有私聊里挑；填了 = 只看这几个 QQ，而且每次醒来逐个都过一遍。每个人能单独设冷场门槛与冷却。 |
| **能先演练再上线** | 「演练模式」打开后，它照样判断、照样想话，但只写进控制台日志，**不真的发出去**。可以先观察几天语气再正式启用。 |

## 设置项一览

设置页按「总开关 → 指定对象 → 叫醒节奏 → 勿扰时段 → 发送限制 → 省 token」六组排列。

### 总开关

| 项 | 默认 | 说明 |
|---|---|---|
| 启用主动私信 | 开 | 关掉后不再自己开口、也不再做任何判断（被动回复不受影响） |
| 演练模式 | 关 | 打开后只写控制台日志、不真发。建议先开几天看语气 |

### 指定对象

| 项 | 默认 | 说明 |
|---|---|---|
| 只对这几个 QQ 主动 | 空 | 空 = 白名单里所有私聊；填了 = 只看这些号，每次醒来逐个检查 |
| 冷场门槛 | 30 分钟 | 对方至少这么久没说话才值得找他 |
| 个人冷却 | 120 分钟 | 同一个人的两次主动之间至少隔多久（对方回话立刻失效） |

**单个人可以单独设**，写法：`QQ号:冷场分钟` 或 `QQ号:冷场分钟/冷却分钟`

```
10001              用上面两个全局值
10002:60           这个人冷场门槛 60 分钟
10003:240/30       冷场门槛 240 分钟 + 冷却 30 分钟
```

多个号用逗号、空格、换行隔开都行；重复自动去重；写错的会在日志里明确提示被忽略。**从没跟机器人聊过的号查不到记录**，会在状态面板和日志里单独列出来提醒。

### 叫醒节奏

| 项 | 默认 | 说明 |
|---|---|---|
| 醒来间隔 | `15-30` | 单位分钟，每次在区间内随机。只写一个数（`20`）= 固定间隔 |

### 勿扰时段

| 项 | 默认 | 说明 |
|---|---|---|
| 睡眠时间 | `00:00-07:00` | 这段内一条都不发。精确到分钟，支持跨零点（`23:00-07:00`） |
| 启用「梁文峰时期」 | 开 | 上班时段禁发的一键开关 |
| 上班时段 | `09:00-12:00, 14:00-18:00` | 可多段；跨零点也认（`22:00-次日02:00`） |
| 上班时段只在哪些天生效 | `1,2,3,4,5` | 1=周一…7=周日。默认只在工作日，周末不受限制 |

### 发送限制

| 项 | 默认 | 说明 |
|---|---|---|
| 每天最多主动几条 | 20 | 全局天花板，不是目标——用不满很正常 |
| 每轮最多发几个人 | `1-1` | 每次醒来最多发几个（区间内随机取上限）。`1-1` 最像真人 |
| 没被回复就不再发第二句 | 开 | 挂起机制，见上文「六个关键特性」 |
| 防重复：刚有机器人发言就别开口 | 30 分钟 | 两道本地保险，不花 token、只会更省 |
| 对方刚回过话就先别发 | 30 分钟 | 对方正在聊，主动让位 |
| 一轮内两条私信之间的间隔 | 20 秒 | 一轮发多人时不刷屏 |

> **关于「每轮最多发几个人」**：它只是上限。实际发出几个取决于 AI 是否同意、对方是否过了冷场/冷却、以及当天还剩多少额度。

### 省 token

| 项 | 默认 | 说明 |
|---|---|---|
| 人设卡片最多发多少字给它 | 0（全文） | **唯一真正影响花费的旋钮**，见下节 |
| 补充要求 | 空 | 只加进「主动开口」这一次的提示，如「别提工作」「别凌晨找我」 |

## 关于花费

这个插件只在**一次判断**上调用 AI。实测一轮的构成：

| 部分 | 占比 |
|---|---|
| **输入：人设卡片** | **约九成** ← 花费几乎全在这里 |
| 输入：最近对话记录 + 判断规则 | 约一成 |
| 输出：一行 JSON + 一句话 | 不到 1% |

人设卡片每问一次就要重发一遍。所以：

- 想省钱，**调「人设卡片最多发多少字」**，填 `3000` 大约能压到五分之一（代价是语气略微变淡）。
- 调小输出上限**没有意义**（输出本来就只用几十个 token）。
- 把「没被回复就不再发第二句」保持打开，是另一个省 token 的主力：被挂起的人根本不会被问。

## 时间口径（重要）

判断材料里给 AI 的每条记录都**带真实间隔**，例如：

```
乐子（10-01，3 天前）：[图片]
机器人（10-01，3 天前）：？这图上不是你吗
乐子（22:16，6 分钟前）：？
```

规则是：**今天的消息只写时刻，往前的带上月-日**，括号里再补一个「N 分钟前 / N 小时前 / N 天前」。同时给 AI 一句明确要求：以「多久以前」为准，**不要凭时刻差自己推算间隔**。

> ⚠️ 为什么必须这样（v1.5.0 修的真实 bug）：
> 早期版本只把「几点几分」给模型，连"现在"也只给时刻。结果一个**三天前**说过话的人（10-01 17:33），在模型眼里变成"今天 17:33"，于是它算出"差三个多小时"，开口就是「三个多小时没动静 你睡了？」。
> **模型没算错，是喂给它的信息缺了日期。** 凡是跨越午夜的间隔，只给时刻就一定会算错；给相对间隔才是可靠的。

## 常见问题

**Q：它会不会一直催同一个人？**
不会。对方没回你主动发的那条，就被挂起，直到他先开口。这跟"冷却时间到了就再试"是两回事。

**Q：我一直在跟机器人聊天，它会不会插嘴？**
不会。「对方刚回过话就先别发」（默认 30 分钟）会让位给正在进行的对话。

**Q：刚聊完一轮，它会不会把"没回"算到我头上？**
不会。判定只认**我主动发出去的那条**有没有被回复。因为对话总是 AI 垫底，如果按"机器人最后发言后对方有没有说话"来判，刚聊完就会被误判。

**Q：为什么它显示「等回复中」但什么都没做？**
这是设计。被挂起的人不进判断名单，连 AI 都不问，所以不花 token。

**Q：为什么一天 20 条却几乎用不满？**
因为上限是天花板。如果指定的人都还没被主动过、或都已回复，它才有对象；一旦指定的人都被挂起，它会安静到有人回话为止。

**Q：需要装别的东西吗？**
不需要。但需要程序已经有可用的 QQ 连接（OneBot HTTP），因为发送走的是那条通道。

## 排障

排障日志默认关闭。需要时设环境变量 `QQ_AGENT_DM_DEBUG=1` 再启动程序，它会把每一步判断写进 `data/silence-ping.debug.log`（包含"当时到底有没有候选、AI 说了什么、发送成功还是失败"）。这是排查"看着在跑却什么也没发生"最快的手段——因为插件的 console 日志不会进程序的日志文件。

## 存档

插件私有存档在 `data/silence-ping.json`，按人一条记录：

```json
{
  "friends": {
    "private:1234567": {
      "lastProactiveAt": 1700000000000,   // 我最后一次主动发出的时间（关键判据）
      "lastProactiveText": "（这里存的是你主动发出去的那句话）",
      "lastIncomingAt": 1699900000000,    // 对方最后一次说话
      "paused": true,                     // 是否处于「等回复中」
      "sentCount": 1
    }
  },
  "dayCount": 6, "lastSendAt": 1700000000000
}
```

每个人的记录完全独立，一个人的挂起不影响别人。删掉这个文件等于让它忘掉所有历史（冷却与挂起状态归零），一般不需要动它。

## 改动本插件时的两个坑

**① 不要用 PowerShell 的 `Set-Content -Encoding UTF8` 改这些文件。**
它会在文件开头写入 BOM（`EF BB BF`），而 `plugin.json` 一旦带 BOM，`JSON.parse` 就会抛
`Unexpected token ''` —— 本地表现为插件加载失败，发布后别人装了也用不了。
要写就用无 BOM 的 UTF-8：

```powershell
$enc = New-Object System.Text.UTF8Encoding($false)
[System.IO.File]::WriteAllText($path, $text, $enc)
```

判断有没有中招：读前三字节是不是 `EF BB BF`。

**② 改 `id` 时必须同时改四处，少一处就会静默失效。**
目录名、`plugin.json` 的 `id`、`plugin.json` 的 `capabilities`（`status.<id>`）、
`index.js` 里导出的能力名与存档/日志文件名。
其中最阴的是 `capabilities`：声明的名字和代码实际实现的对不上时，插件照样显示 `active`，
只是那个状态项永远不工作。改完用下面两行核对「声明」与「实现」是否一致：

```powershell
$s = (Invoke-RestMethod http://127.0.0.1:3210/api/skills).skills | ? id -eq 'silence-ping'
$s.capabilities; $s.implementedCapabilities   # 两者必须相同
```
