# 🐋 矩阵庭院（travel-whale）

每个群养一只小鲸鱼。它会**自己出门旅行、从世界各地寄明信片回来、带回特产**，
攒久了还能解锁称号。群里的人只需要偶尔喂它。

```
🐋 我出门啦 —— 这趟去 中国·兰州
🖼️ [一张明信片配图]
💬 嘿嘿，到了
   桥底下风好大，黄河水真是黄的，跟我猜的一样。站在铁桥上往下看腿有点软，不过没跟你们说。
🐋 我回来啦。这趟去了 中国·兰州。
   带回来的东西：兰州牛肉面、黄河奇石（稀有！）
🌌 解锁称号：踏进星野 —— 完成第 1 次旅行
```

- **归属**：每个群 / 每个私聊各养一只，状态互不相通
- **白名单制**：显式列名单，或主人说一句「在这养一只鲸鱼」
- **零编程**：所有配置都在控制台的技能设置弹窗里

## 一、怎么玩

### 上手三步

1. 控制台 → **技能** → 开启「矩阵庭院」
2. 群里说「**在这养一只鲸鱼**」
3. 等几分钟 → 「**收一下 TOKEN**」→「**买一份中份大白饭**」→「**让它出门吧**」

之后它会自己寄明信片回来。

### ⚠️ 面板类结果**直接发群**，不经过模型

「看商店 / 看庭院 / 看相册 / 看称号」这几类，用户要的就是**那份清单本身**。
但模型拿到工具结果后会**按人设重新措辞**（小鲸鱼是"1~10 字、像真人"）——
实测问「看一下商店」，整张价目表被压缩成了 4 句短消息。

所以这几个工具走 `replyPanel()`：**把面板原样发到群里**，只回给模型一句
「内容已直接发到群里。不要再复述、总结或补充。」

### 核心循环

```
收 TOKEN ──► 买大白饭/护身符/装备 ──► 让它出门 ──► 等明信片 ──► 它自己回来
     ▲                                                                  │
     └──────────────────────────────────────────────────────────────────┘
```

⚠️ **要喂它**：没有口粮它就不会出门。这也是唯一的日常负担。

## 二、玩法细则

### TOKEN（唯一货币）

| 项 | 值 |
|---|---|
| 产出速度 | **8 小时产出满载**（基础 125 亿 TOKEN/小时、上限 1000 亿 TOKEN；建了**服务器阵列**会按台数翻倍）—— 基础值改 `state.js` 的 `POND_FILL_HOURS` |
| 服务器上限 | **1000 亿 TOKEN**（够存一整套装备） |
| 收取冷却 | 5 分钟 |
| 稀有掉落 | 2% 捞到 ✨发光 TOKEN |

> **懒计算**：不存"现在有多少"，只存"上次结算是什么时候"，需要时按时间差算。
> 所以进程重启、关机三天、多实例，状态**自动正确**，不需要任何补偿逻辑。

| 中份大白饭 | 50 | 20 | 走 8~16 小时（途中 **2~3** 张） |
| 大份大白饭 | 100 | 20 | 走 16~24 小时（途中 **2~4** 张） |

| 😈 小魔王 | 3500 | 「惹事」 | 吃 2 份 ／ +50% ／ ×2 ／ 异世界必惹事（多 1 张战斗明信片） |
| 🪭 **小折扇（千问）** | 3500 | 「**垦殖**」 | 吃 2 份 ／ +50% ／ ×2 ／ **请过就永久有菜地（4 块）**；她在庭院时**种下**的那株快 30% |
| 🦊 黑发兽耳小狐狸 | 4000 | 「免费鸡蛋」 | 吃 2 份 ／ +50% ／ ×2 ／ **每天 +500 亿 TOKEN**（学了「不请自来」→ 800） |

| 🐉 小白龙 | 5000 | 「大肥龙」 | 吃 3 份 ／ 明信片 +100% ／ **稀有 ×3** |

- ★ **定价口径（用户 2026-10-14）**：最贵最强是**国模范畴** —— 小月亮是国模里最贵的（4500），
  但**不比小白龙（5000）贵**。小折扇按口径降回 3500（与小魔王同价是可以的，不要求两两不同）。
- ★ **v3.2 两位新旅伴都改绑特产**：小月亮「博闻」（写批注 + 收成 +1）、小折扇「垦殖」（开菜地 + 加成）。
  原来的「随记」（多 1 张，与小书虫撞口子）与「说书」（张数 +100%）都已去掉。
- **邀请制（不再"只能有一个"）**：一共 7 位（小狐狸 / 小白龙 / 小书虫 / 小猫咪 / 小魔王 / 小月亮 / 小折扇），**请过就一直跟着出门、可随时换人**（在途时换不成，回家才落定）；不占货架库存、不进背包计数（所以走独立分支，不进 `shopTable`）
- **闲置伙伴会自己出去玩**（2026-10-13；**10-14 起支持同时多趟**）：没被带着的伙伴凑够**两人一组**、背包里某一档米饭 **≥6 份**就会自己出门 —— 拿走 2 份饭、回来固定带 1 件特产；能同时开几趟 = `floor(闲置人数 ÷ 2)`（**七位全请到时：6 位闲置 ⇒ 三趟**），各趟互不干扰、各有各的归期与明信片
- 买了之后**她俩一起出门**：`depart()` 扣两份口粮（不够**两份**就明确拒绝出发，且**一份都不扣**）
- 从那以后的明信片是**双人构图**（`postcard.js` 的 `FOX_CHARACTER` + `DUO_FUSION_TEMPLATES` + `DUO_NEGATIVE_HINT`）
- 概率是**乘在最终值上**的：`(基础10% + 护身符 + 首访) × 2`，所以和护身符**可叠加**（戴深海珍珠 + 带狐狸 = 60%）
- ⚠️ `rareMult` **只放大明信片稀有度**，不动特产稀有度（后者由 LLM 打标签起步，口径不同）
- 相册里双人片的行首会带 🦊 标记（`album[].companion`）

### 出行：两条触发路径

**手动** —— 群友说「让它去旅行」，工具立刻调 `depart()`。

**自动** —— 后台 ticker 每 60 秒判定一次，三个条件**全满足**才走：

1. 没有进行中的旅程（在家）
2. 背包里有口粮
3. `now >= nextDepartAt` 且**不在夜里**（0:00~7:00）

**⚠️ 群聊和私聊的规则不一样：**

| | 会自动出门吗 | 说明 |
|---|---|---|
| **群聊** | ✅ 会 | 群友养的宠物，自己出门才有惊喜感 |
| **私聊** | ❌ **不会** | 只有你明确说「让它去旅行」「出门吧」才走 |

> 私聊不自动出发的理由：群聊是「大家养的」，自己出门是惊喜；
> 私聊是「你自己的一个人」，未经同意就往你这儿推消息是**打扰**。

`nextDepartAt` 的基准是「**「我回来啦」播报真正发出的时刻**」+ 随机 **24~48 小时**，
落在夜里则顺延到次日 7:00。

> ★ 2026-10-13（大更新 step3）：原来是 **2~6 小时** —— 用户报「**家存在感太弱**，回来踩一脚就走」。
> 中份饭走 8~16 小时、回家只歇 2~6 小时 ⇒ **在家的时间只占循环的 11%~43%**，家自然像客栈。
> 改成 24~48 小时后，在家时间占循环的 **50%~75%**。
> 实际取值可由设置 **`restHoursMin` / `restHoursMax`** 覆盖（改配置即生效，不用重启）；
> ⚠️ **两条自动出门共用这一个函数** —— 她自己那趟与「闲置伙伴自己跑出去玩」那趟一起变。

> 为什么用「播报时刻」而不是「到家时刻」：夜里到家的播报会被压到早上 7 点补发，
> 若按到家时刻排，就会出现「早上 7 点刚说『我回来啦』、转头 8 点又出门」的诡异时间线。
> 压住期间 `nextDepartAt` 置 0，自动出发会被拦下，它不会偷偷溜走。

### 一趟旅程的完整时序

```
① 出发
   ├─ 装备 → 大区（没装备默认亚洲）
   ├─ 口粮 → 时长
   ├─ 护身符自动消耗 1 件
   ├─ 选城市：内置池 80% / LLM 自由发挥 20%
   ├─ 搜「景点」+「特产」→ LLM 抽取（防幻觉 + 跑题校验）
   ├─ 抽画风（每趟只用一种）
   └─ 排明信片时刻（每 4~8 小时一张）
   → 群播报「我出门啦」

② 旅途中 —— 每张明信片
   ├─ 写文案（题字 + ~50 字感想）→ 生图
   ├─ 发一条图 + 一条文字
   └─ 夜里 0~7 点压住，天亮补发

③ 归来
   ├─ 整趟都在夜里没寄成 → 补寄最后一张（避免"出门啥都没留下"）
   ├─ 记到访（城市 + 景点两套）
   ├─ 特产入图鉴（稀有的生成图；**首次拿到才画**）
   ├─ 判定称号 → 逐个播报
   → 群播报「我回来啦 + 带回的东西」+ 稀有特产图
   └─ 排下次自动出发
```

**三个防刷屏设计**：明信片第一张**不立刻发**（等第一个 4~8h 窗口）；
一次 tick **最多寄一张**；夜里**完全静默**。

### 明信片

**张数由口粮档位决定，出行前就抽定**（写进 `trip.cardTimes`，之后不重算）：

| 口粮 | 途中张数 | 第一张 |
|---|---|---|
| 小份 | 1~2 张 | 最晚 4.5h |
| 中份 | 2~3 张 | 最晚 5.9h |
| 大份 | 2~4 张 | 最晚 8.0h |

→ **硬约束：出发后 8 小时内一定会有一张**（防止「出门半天群里一点动静都没有」）。
排法是把旅程等分成 N+1 段、每张落在段中心，再加 ≤12.5% 抖动。

**画图有「两个正交的轴」**，都在出门前各定一种：

| 轴 | 是什么 | 池子 |
|---|---|---|
| **地区画风**（`style`）| 整幅画的媒介与笔法 | 按大区走，共 39 种（水墨写意 / 油画厚涂 / 极光渐变…） |
| **人物画法**（`charStyle`）| **人物本身**的比例与笔触 | 5 种等概率：Q版日系插画 / 日系动漫插画 / 半写实插画 / 绘本插画 / 赛璐璐平涂 |

两者自由组合，比如「油画厚涂 + Q版二头身」「极光渐变 + 半写实七头身」。
**人物画法里刻意不写“水墨/油画”这类媒介词** —— 那是地区画风的活，写进来会打架。

**「每张寄什么」也在出门前定死**（`trip.cardPlan`，含到家那张）：

```
按顺序给每张分配一个「没用过的景点」；
景点用完了 → 剩下的那张改做【特产明信片】（主题是这趟带回来的东西）
```

> **为什么要这条**：景点只搜到 1~2 个，而明信片可能有 3 张（2 途中 + 1 到家）。
> 按老逻辑硬铺必然出现「同一个景点连寄两张」，读起来像卡带。
> 让多出来的那张讲特产，既避免重复，也让「回来带了什么」这条线有地方交代。

| 景点数 vs 卡片数 | 分配结果 |
|---|---|
| 2 个景点 / 3 张 | 景点A → 景点B → **特产** |
| 3 个景点 / 3 张 | 景点A → 景点B → 景点C |
| 1 个景点 / 3 张 | 景点A → **特产** → **特产** |

特产明信片的**文案**（写带回的东西、对它们的评价）和**配图**（捧着的特产 + 景点作背景）
都走单独分支，不会又是一张风景照。

**到家时还会再寄一张**（不计入上面的张数），和特产播报一起 ——
这就是需求里的「到家之后反馈明信片和特产」。夜里到家则连明信片带播报一起压到早 7 点。


- 结构：**题字（≤12 字，小鲸鱼口吻）+ 配图（地区特色）+ 感想（~50 字，第一人称旅行日记）**
- 走**独立提示词** —— 明信片是旅行日记，不受群聊"1~10 字"铁律约束
- 画风：每趟只用一种，共 **39 种**（水墨/浮世绘/油画/波普/极光…），按地区配池
- 失败降级：文案失败→本地兜底话术（**保证有字**）；生图失败→**退化为纯文字明信片**

### 在家的大合照（「矩阵庭院」，2026-10-13 大更新 step4）

★ 她在家的时候也寄"明信片" —— 但拍的是**大合照**。

| | 旅行明信片 | 在家的大合照 |
|---|---|---|
| 触发 | 出门旅行途中 / 到家 | **回到家、并且在家待满 `homeShotHours`（默认 8）小时** |
| 张数 | 按档位 0/1/2~4 张 + 到家 1 张 | **每趟回家只拍 1 张** |
| 画幅 | 方板（`imageSize`，默认 1024x1024） | **横板（`homeShotSize`，默认 1536x1024）** |
| 构图 | 她（+ 同行伙伴）在景点 | **举着镜头自拍**：她自己伸一只手臂把镜头举到面前（轻微广角畸变） |
| 人物 | 她自己 / 她自己 + 1 位旅伴 | **她自己 + 所有在家的旅伴**（正在自己出去玩的**都不入镜** —— 可能不止两位，见下） |
| 背景 | 目的地 | **矩阵庭院** —— 一座能**看见满天星星**的院子 |
| 相册 | `kind: 'spot' / 'souvenir'` | `kind: 'home'`，且**不计入「已寄明信片 N 张」** |

- **"所有在家的 AI 娘"** = 她 + 已邀请的全部旅伴；一个都没邀请时退化成"她在庭院里的自拍"。
- 夜里（0~7 点）不拍（跟"她夜里在睡"一致）；`homeShotHours` 填 **0 = 关掉这个玩法**。
- 生图失败 / 文案失败**都不抛**：能发的照发（图没有就纯文字），并且**照打 `homeShotAt` 标记** ——
  否则每个 tick 都会重试一次（刷屏）。触发判据是纯函数 `home.js` 的 `shouldShootHome()`。
- 它确实进相册 ⇒ **空间日记挑配图时也会挑到它**（`qqzone` 只按"今天真寄出去的"过滤，不看 kind）。

### 她在家"此刻在做什么"（`home.js` 的 `HOME_ACTS`，2026-10-13；按旅伴分档 = 2026-10-14）

回到家、人都在的时候，她不是干站着 —— 系统每 **20 分钟**从池子里抽一条"她此刻在庭院里做什么"，
写成一行状态（`在矩阵庭院{act}`），**同一条真源**同时喂睡眠情绪插件与世界书（俩都只读，不各算一份）。

- **三档池子**：只有她自己能做的（擦镜头、数星星…）／**得有人一起**的（`mate: true`，
  院子里一个旅伴都没有时不参与抽选）／**升级才出现的**（`eaves: N`，檐廊升到 N 级才进池子）。
- ★★ **按旅伴绑定的条目**（`mateId: 'fox'` 等，2026-10-14 补）：**七位每位 2 条**专属互动
  （小狐狸的尾巴当毯子、小月亮的册子、小折扇在菜畦边松土…）。
  只有**那位在家**才进池子，而且 `{mate}` 一定填成**她本人**（通用条目才是从"在家的几位"里随机挑）。
  ⚠️ 认不出 id（比如老存档 / 新旅伴还没接线）一律当"不在"，**安全降级**。
- ⚠️ 条目若断言"院子有某物"必须打标记：`needsFarm: true`（＝菜地以外才会出现的写法），
  否则会出现"在没有菜畦的院子里在菜畦边松土"（同 `travel-states.js` 的 `need` 纪律）。
- 稳定性：抽取由 `hash(chatKey|homeSince|20 分钟桶)` 决定 ⇒ 同一段时间内结果一致（面板不抖）。
  幂等键用 **id**（不用显示名 —— 改名不该被当成"变了"）+ 檐廊等级 + 有没有菜地。

#### 矩阵庭院长什么样（`home.js` 的 `HOME_SCENE`）

用户点名的硬要求：**这里必须是一个能看到星星的地方**。「矩阵」= 星轨/网格般整齐的星野 + 数据流光，
「庭院」= 日式院子，两半都要在画面里看得见：

- 青石板地，石缝里淌过极细的淡蓝色数据流光；院子中央一方**倒映星空的水镜**；
- 檐下石灯笼的灯箱做成**老式服务器机柜**的样子（与玩法里的「服务器」同一套世界观）；
- 横廊矮桌与坐垫、斜向水面的老树、叶隙间垂着的发光藤蔓；半空飘着萤火与数据光点；
- ★ **夜空看得见星星**：无光污染、无云，星点密得像撒了盐，一条银河横跨；
  星点的排布隐约整齐得像一张漫天网格 —— 这正是「矩阵」这个名字的来处。

**画风组**（`HOME_STYLES`，6 条）。⚠️ 与 `regions.json` 的地区画风**刻意区分**：全部是"夜景 + 星光"
取向的一小组，这样同一座庭院在不同夜里拍出来气质一致（旅行明信片才百变）。
每张合照只抽一种（与"每趟只抽一种画风"同理）。

### 归来奖励：**只认稀有**

|"撞上什么" | 奖励 |
|---|---|
| 稀有特产 | **+50 亿 TOKEN** / 件（一趟最多 1 件）|
| 稀有明信片 | **+20 亿 TOKEN** / 张 |
| **两样都没有** | **不给**，播报里也不提这一行 |

> **为什么不按趟发**：原来设计写的是「归来给一小笔 TOKEN」，但那等于每趟都发，
> 出门就变成净赚，口粮不再是成本。改成只认稀有那么一档之后 ——
> **普通的一趟颗粒无收，撞到稀有的那趟才有惊喜**，冲稀有这件事也就有了实际收益。

播报长这样：
```
✨ 这趟撞上稀有特产 ×1、稀有明信片 ×2，额外捡到 90 亿 TOKEN
```

### 稀有的概率

**稀有特产**：`p = LLM标签基础 + 护身符luck + 首次获得15%`

| LLM 标签 | 裸奔 | +海螺 | +护符 | +珍珠 |
|---|---:|---:|---:|---:|
| `common` | **5%** | 17% | 30% | 45% |
| `uncommon` | **35%** | 47% | 60% | 75% |
| `rare` | **100%** | 100% | 100% | 100% |

**稀有明信片**：`p = 10% + 首次到访10% + 护身符luck × 0.5`

| 场景 | 裸奔 | +海螺 | +护符 | +珍珠 |
|---|---:|---:|---:|---:|
| 常规 | **10%** | 16% | 22.5% | 30% |
| 首次到访 | **20%** | 26% | 32.5% | 40% |

**硬上限的判定顺序**：先按标签排序（`rare` → `uncommon` → `common`），再逐件掷骰子，
`rare` 标签**优先占用**「每趟 1 件」的名额。

> ⚠️ 不排的话硬上限就成了「**先到先得**」—— 一件 common 掷中了，会把后面标着 rare、
> 本该 100% 必出的那件挤成普通。实测（4 件特产含 1 件 rare 标签）：
> **奇石被挤掉的概率 80%~96.5%**，LLM 打的 rare 标签形同虚设。
> 排序之后：有 rare 标签 → 它 100% 是那件稀有；没有 → 才轮到 common/uncommon 掷骰子出惊喜。

**趟级概率**（20 万趟模拟，含「一趟最多 1 件稀有特产」硬上限）：

| 场景 | 稀有特产 | 稀有明信片 | 至少一个 |
|---|---:|---:|---:|
| 小份 2张 / 3特产 common | 49% | 19% | **58%** |
| 中份 4张 / 3特产 common +首次 | 49% | 59% | **79%** |
| 大份 5张 / 4特产 uncommon +珍珠 | 100% | 92% | **100%** |

### 景点明信片 vs 特产明信片

出门前分配卡片时，**景点不够铺满**就会把多出来的那几张改成「特产明信片」：

| | 📍 景点明信片 | 🎁 特产明信片 |
|---|---|---|
| **何时出现** | 默认 | 景点数 < 卡片数时，多出来的那些 |
| **文案提示词** | 「你此刻在 越南·会安，**站在「日本廊桥」前**」 | 「你已经收拾好行李，**准备回去了**。这张要写的是**这趟带回来的东西**：会安灯笼、会安丝绸」 |
| **感想写什么** | 此刻看到的、想到的 | 把东西装进行李时的心情、对它们的评价 |
| **配图场景** | `场景：木桥、流水与倒影` | `场景：捧着的特产：会安灯笼、会安丝绸；背景是木桥、流水与倒影`（特产是**主体**）|
| **存档字段** | `kind:'spot'` | `kind:'souvenir'` + `souvenirs:[...]` |
| **稀有度** | 独立掷骰 | 独立掷骰（和景点片共用同一套规则）|

> 到家那张**固定排在卡片序列的末尾**，所以景点不够时它自然就成了特产明信片。

> ⚠️ **但只有真的有特产可讲时才会变**。搜到资料却一件特产都没抽出来的情况是存在的
> （实测庆州那趟：搜到 8 条特产资料，抽取结果 0 件）—— 那时若还硬造一张特产卡，
> 提示词里的「捧着的特产：」后面就是空的，文案会开始编。**没特产时改为循环复用景点**。

| 条件 | 多出来的那些卡 |
|---|---|
| 有特产 | 🎁 特产主题 |
| **没特产** | 📍 景点（**循环复用**，至少不空）|

### 稀有明信片（✨）

每张明信片在**出门前**就会抽定是不是稀有（写进 `trip.cardPlan[].rarity`）：

| 来源 | 加成 |
|---|---|
| 基础概率 | **10%** |
| 第一次来这座城市 | **+10%** |
| 护身符 | 海螺 +6% / 护符 +12.5% / 珍珠 +20% |

→ 区间 **10% ~ 40%**（裸奔 → 珍珠 + 首次到访）

> 护身符的加成在这里**乘了 0.5**：它的 luck（0.12/0.25/0.40）是照着特产的
> 概率区间调的，直接套到只有 10% 基础的明信片上，戴珍珠就能到 50%，稀有就不稀有了。

**稀有明信片长什么样**：

- **画面**：生图提示词追加「电影级光影、更精细的笔触、画面边缘一圈淡金色光晕」
- **题字**：前面加一个 `✨`，群里一眼能看出
- **相册**：条目存 `rarity:'rare'`，列表用 ✨ 标出；`stats.rareCards` 计数
- **控制台**：明信片计划里用 ✨ 标出哪张是稀有的

> 措辞上刻意**避开「边框」二字** —— 构图约束里明确写了「不要边框」，
> 写成「金色边框」两条指令会打架，模型多半会画一个突兀的相框。

### 特产与稀有度

**普通** = 纯文字；**稀有** = 生成图（特产 + 城市背景 + 鲸鱼捧着）+ 存图鉴。
**图会发出来**：随「我回来啦」的归家播报一并发送（夜里压进 `pending.images`，天亮补发）；
图鉴页顶部有三列**稀有特产图墙**；群友说「**看图鉴里的 某某**」会直接发那一张原图。
生图与明信片共用同一套人设拼装（`buildSouvenirPrompt`：服装 / 人物画法 / 世界观 / 情境 / 解剖约束）。

判定三层：

1. **LLM 打标签**：`common`（牛肉面/冰箱贴）/ `uncommon`（百合/精油）/ `rare`（奇石/非遗手作）
2. **概率修正**：rare 100%｜uncommon 35%｜common 5%｜**护身符 +12~40%**｜**图鉴没得过 +15%**
3. **硬上限：每趟最多 1 件稀有**（否则稀有就不稀有了）

重复获得只累加计数，**不再出图**（省成本 + 保住稀有感）。

**三档各有各的标记**（以前 `uncommon` 和图鉴里显示得跟 `common` 一模一样，等于白标了一档）：

| 档位 | 图鉴标记 | 归来播报 | 配图 |
|---|---|---|---|
| `common` 普通 | `·` | 只写名字 | 无 |
| `uncommon` 罕见 | **`✦`** | **名字后带 `✦`**，并附一句「✦ 是罕见特产」 | 无 |
| `rare` 稀有 | `💎` | 名字后带 `（稀有！）` | **有** |

「看相册」里还会单独列一行 `✦ 罕见 N 件`。

> 顺带一提：护身符的加成对**特产**是全额、对**明信片**要乘 0.5，
> 所以商店和说明图里都写成两栏（「特产稀有 +12% / 明信片 +6%」），不再混成一个数。

### 特产不是只能收着（2026-10-14，v3.2）

带回来的东西**第一次有了出口**。三条路，说一句话就行：

| 动作 | 怎么说 | 消耗 | 得到 |
|---|---|---|---|
| 🍽️ **吃掉 / 喝掉** | 「吃掉那个冰淇淋」 | 1 份存量 | 按口味的一句感想 + 心情 + **之后 5/15/30 分钟的「余味」**（按稀有度，见下） | 
| 🎀 **送给群友** | 「把京扇子送给某某」 | 1 份存量 | 公开具名播报 + **永久记在收礼人名下**（以后能被问起"她送过我什么"） |
| 🌱 **种进菜地** | 「种下神之麦」 | 1 份存量 | 3~5 天后收 **2~4 份**（净赚） |

三条铁律：

- **用一次只扣 `stock`（可支配存量），`count`（累计带回次数）一点都不动** ——
  「收集 N 件」看的是**条目数**，所以吃光送光也**不会把图鉴清掉**。
- **吃 / 送会先犹豫一句**（「诶，真的要吃吗」）—— **第一次调用不消耗任何东西**，
  换个唤醒会话再说一次才真动手（同一轮连调两次不生效，否则模型会自己把自己确认掉）。
  种下**不问**：东西没消失，它会长出更多份。
- **吃不给 TOKEN，收成稀有作物才给**（对齐"只有稀有特产带回来才给 50 亿 TOKEN"）。

**「余味」（v3.7）**：吃 / 喝下去**不是立刻就算完** —— 接下来一小段时间她说话会带着那个味道。
时长按稀有度 **5 / 15 / 30 分钟**（普通 / 罕见 / 稀有），按**口味**给六套演法：

| 口味 | 吃到什么 | 之后怎么说话 |
|---|---|---|
| `drink` | 酒、酿 | 有点上头：句子松、话变多，容易笑、容易说漏心里话，嘴上还硬撑"我没醉" |
| `spicy` | 辣椒、姜、蒜 | 一边吸气一边嘴硬："呼……""嗬……"，短句、急着找水 |
| `sweet` | 冰淇淋、布丁、点心 | 语气软一点、句子带笑意 |
| `tea` | 茶、抹茶 | 慢半拍、稳一点，不急不躁 |
| `staple` | 饭、面、肉 | 真的饱：发懒、犯困，句子变短，"不想动了" |
| `other` | 其它 | 顺口提一句就好，别刻意 |

通道：travel-whale 只往**自己的存档**写一条 `state.foodAfter`，sleep-mood 的
`lib/travel-sync.js` **只读**它、拼成 `【自身状态·刚吃完】…` 注进提示词 ——
与 `travelPromptText`【在路上】/ `homePromptText`【在庭院】**同一个出口**（三兄弟）。
★ **一条真源，两边不各算一份**（同 §67 的 `homeAct`）；**过期只在读侧判**（`until > now`），不写清理。

**看图鉴**：说一句「看图鉴」会发一张**图鉴页**（第 5 张菜单图）—— 按稀有度分组，
每件写清「从哪儿带的 / 能不能吃 / 能不能种 / 手上还剩几份 / 吃过送过种过几次」；
**存了图的稀有特产**在页顶有图墙（缩略图三列）。
单独点名「**看图鉴里的 某某**」则直接发那一张原图（`whale_pantry` 的 `item` 参数）。
在此之前特产只在相册里露一行、而且**只列前 12 件**（15 件时就已经有 3 件看不见了）。

**菜地**：先请一次**千问（小折扇）** ⇒ **永久解锁**（地是她开垦的，之后她在不在家都能种）。
请过就是 **4 块**（她另开的 1 块**是永久的** —— 不会因为她出门就少一块，见下）；
普通/非普通 **3 天**、稀有 **5 天**（5 档：播种→发芽→长高→结蕾→成熟，**每长一档播一条**）；
产出 **4 / 3 / 2** 份。

> ★ **"她在不在家"只影响一件事：她在庭院时*种下*的那株周期 ×0.7**（倍率在种下那一刻冻在株上）。
> **地块上限不看她在不在** —— 曾经写成"她在庭院时才多 1 块"，于是她一出门上限掉回 3、
> 界面出现"4/3 块"这种自相矛盾的显示（用户原话："她要是出门了那块地就凭空消失吗，上面的特产呢？"）。
> 规矩：**凡是"她走了就会少掉"的东西，一律不做** —— 要么永久，要么只改速率。

`学遍诸界`（全部技能）、`流水成河`（累计 5 万亿 TOKEN）、`小有所成`（解锁一半称号）、`一个不落`（解锁全部称号）。
在「看称号」与状态面板里显示成 `🏅 已解锁 N/57（成就值 M/228）`。

★★ **成就值的用途：建造「服务器阵列」** —— 庭院设施里**唯一不花 TOKEN** 的一件。
最多 **4 台**，门槛是成就值：**10 / 50 / 100 / 全部成就值** 分各建一台（末位那个是**动态**的，
以后每加一条称号它自己往上抬）。每建一台，就多一份**基础产出与储量上限**
（基础 = 1000 亿 TOKEN ÷ 8 小时 = 125 亿 TOKEN/小时）：

| 台数 | 产出 | 储量上限（亿 TOKEN） | 需要成就值 |
|---:|---:|---:|---:|
| 0 | 125 亿 TOKEN/小时 | 1000 | — |
| 1 | 250 亿 TOKEN/小时 | 2000 | 10 分 |
| 2 | 375 亿 TOKEN/小时 | 3000 | 50 分 |
| 3 | 500 亿 TOKEN/小时 | 4000 | 100 分 |
| 4 | **625 亿 TOKEN/小时** | **5000** | **全部成就值** |

⚠️ 现在总分 **228** ⇒ 第四台实际是"几乎全收集"级的目标；「称号本身」那两条 10 点（共 20 分）
一直是最后一段的关键。
倍率只在 `state.js` 的 `arrayMult()` 定义一次，产出（`growPond`）与储量（`pondReady`）都读它，
显示统一走 `pondStats()` —— **别再手写固定的产量数字**（建了阵列之后它就不是常数了）。

★ 两条「称号本身」：`🎖️小有所成`（解锁一半称号）、`💯一个不落`（解锁全部称号），**都 10 点**（用户指定）。
⚠️ 它们的判据**跳过自己这一组**（`titleProgress()`）—— 否则"集齐全部"要求"拿到它自己"，**自引用死锁**。
⚠️ 同理，「服务器阵列」那件设施**没有 TOKEN 价**（`prices: []`），门槛走独立字段 `pointCosts` ——
两种币种混用同一个字段迟早算错。

★ **TOKEN 那组只做"余额"与"累计赚取"两类**：
- 余额 = `wallet.plankton`（手上有多少）；
- 累计 = **流水**，记在 `state.stats.earned`，只在**加钱**时累加
  （收 TOKEN / 归来奖励 / 每日津贴 / 新手礼包），花掉不扣 ⇒ 不会被消费抹平，是真正的长期目标。
  ⚠️ 这本账是**这一版才加的**，老存档读出来是 0 ⇒ 判定时用**余额兜底**（不会把老档判成"没挣过钱"）。
  ⚠️ 以后加钱请一律走 `grantPlankton()`（它自己会记账），**别再直接改 `wallet.plankton`**。

★ 2026-10-13 晚重整（**只改名字、条件一律没动**）：

- 可以**脱离 Electron / 网络环境单测**（本项目的端到端测试正是这么跑的）；
- 不会出现"谁调用谁"的循环依赖；
- 换搜索源、换生图后端、换模型，都不用动这些文件。

只有 `index.js`（装配层）和 `search.js`（搜索层）碰外部世界。

## 四、⭐ 核心架构变化

**这个技能需要核心开一个口子**：把 `sender` / `reminders` 等核心实例暴露给技能。

理由很直接：工具能拿到的 `ctx`（含 `sender`）**只在工具被调用时才有**，
而鲸鱼寄明信片、回家、自动出发**都发生在没有工具调用的时刻**（后台定时器驱动）。

改动是**纯新增**，涉及三个文件：

| 文件 | 新增 |
|---|---|
| `src/skills/manager.js` | `setServices()` / `get services` / `onServices()` |
| `src/plugin-loader.js` | `api.services()` / `api.onServices(fn)` |
| `src/app.js` | 服务构造完后 `skillManager.setServices({...})` 注入一次 |

> 📄 **完整补丁说明、代码、回滚方式见同目录的 [`CORE-PATCH.md`](./CORE-PATCH.md)。**

**这个口子是通用的**，不止服务鲸鱼 —— 任何"定时推送 / 自主发言 / 后台轮询"类技能都需要它。

## 五、搜索层

### ⚠️ 查询必须带国名

```js
search(`${country} ${city} 最著名的景点 名胜`)
search(`${country} ${city} 有什么特产 特色`)
```

**不带国名会被地名歧义坑。** 实测搜「庆州 有什么特产」，百度返回的是**甘肃庆阳**
（庆城县 / 华池县 / 庆阳香包 / 环县羊羔肉）—— 完全另一个地方。

> 跑题校验拦不住：它只看「结果里有没有出现城市名」，而第一条标题恰好就叫「庆州」。
> 改成「韩国 庆州 有什么特产」后，立刻回到韩国庆州（庆州佛国寺五味子茶、皇南饼、庆州韩牛）。

### 三级链路

```
串行队列（全局唯一，同一时刻只有 1 个在途请求，间隔 ≥ 1100ms）
   ① 百度搜索               /v2/ai_search/web_search      免费 50/天
   ② 智能搜索生成高性能版    /v2/ai_search/web_summary     免费 100/天
   ③ Bing                   （免 Key，无限）
   ④ LLM 自带知识            （最后兜底）
```

| 设计 | 原因 |
|---|---|
| **串行 + 限速** | 千帆默认 1QPS，并发直接返回 `RATE_LIMIT_SEARCH_QPS`（实测撞过）。队列即使抛错也保持不断，否则一次失败会毒化后续全部请求 |
| **本地记配额** | 默认「不自动花钱」：用满免费额度就降级，而不是让账单悄悄上涨 |
| **失败不计入配额** | 否则一次超时就把免费额度吃掉了 |
| **Key 优先级** | 技能自有 → 全局搜索配置 → 环境变量 `BAIDU_SEARCH_API_KEY` |

### 两个防幻觉闸门

搜索结果和模型输出都是**不可信输入**，所以：

1. **只许摘不许编** —— 把搜索到的资料全文喂给模型，要求"只能从资料里提取"；
2. **出处校验** —— 抽出来的景点/特产名必须在资料里找得到依据，否则丢弃。

> ⚠️ 第 2 条踩过一个真实的坑：片段匹配原本从 **2 字**起，结果"莫须有**特产**"
> 因为含"特产"二字通过了校验 —— 而搜索结果的**标题**里几乎必然出现"XX特产大全"。
> 于是编造的名字只要沾上通用词就能蒙混过关，防幻觉形同虚设。
> 现已改成：**最短 3 字 + 通用词黑名单**（特产/景点/美食/攻略…）。

### 跑题校验

搜索结果可能**跟目标城市无关**（引擎返回了别的城市的内容）。如果标题+摘要里
**一次都没提到城市名**，就判定跑题，改走"模型知识兜底"，而不是硬把别人的景点
安到这座城市头上。

## 六、选城市：池子 80% / 自由 20%

| 路径 | 做法 |
|---|---|
| **池子（80%）** | 从内置地区表（9 地区 / 90 国 / **889 城**）里挑。真实、有名、分布均匀 |
| **自由（20%）** | 让 LLM 在大区内自由发挥，去池子外的城市 —— 保留惊喜感 |

**自由路径有两道闸门**，任一不过就回落池子：

1. **大区归属校验** —— 模型自称的地区必须对得上（防止"选亚洲却给了开罗"）；
2. **不撞已去过** —— 撞了就丢弃。

**再加一道**：自由路径挑中的城市，如果后续**搜不到景点**，判定"这地方没玩头"，
`depart()` 会**回落池子重挑一次**才放弃。这是"自由发挥不翻车"的保证。

### "尽量不重复"用的是**加权**，不是硬排除

```
没去过      权重 10
去过 1 次    权重 3
去过 2 次    权重 1
去过 3 次+   权重 0.5        ← 永远不为 0
```

实测：兰州去过 5 次后中签率是平均城市的 **0.04 倍**，但**永不归零**。

好处：池子**永远不会"用完"**，也就不需要写"池子跑完怎么办"这种特例。
而且"故地重游"本身就是个称号，重复去是合理的。

## 七、数据与存储

全部落在 `DATA_DIR/skills/travel-whale/` 下（`DATA_DIR` 默认是 **exe 旁边的 `data/`**，
由 `electron/main.js` 在加载 config 前设好；多实例下是 `data-2/` 等）。

```
data/skills/travel-whale/
├── chats/<group_123>.json     每群一只鲸鱼的完整状态
```

**文件名沿用核心 store 的约定**（`group:123` → `group_123.json`），
避免出现 `:` 这类在 Windows 上非法或易出问题的字符。

## 十一、⚠️ 改这个技能时必读：热重载的边界

**热重载只重载 `index.js`，不会重载子模块。**

加载器用 `import(entryUrl + '?t=' + Date.now())` 强制刷新入口，但 `index.js` 里的
`import './state.js'` 解析出来还是**不带时间戳的原 URL** —— Node 的 ESM 模块缓存
按 URL 记，于是子模块**永远是进程启动时那一版**，直到重启。

| 你改了什么 | 热重载生效？ |
|---|---|
| `index.js` | ✅ 生效 |
| `state.js` / `trip.js` / `postcard.js` / `search.js` / `titles.js` / `engine.js` / `help.js` | ❌ **必须重启应用** |
| `skill.json` / `data/regions.json` | ✅ 生效（清单与数据是每次热重载重读的） |

**更坑的是**：热重载失败时加载器走 `hadPrevious` 分支，**只把错误记进内存、不写日志**。
日志里你只会看到 `skills/：21 成功，1 失败`，完全不知道是谁、为什么。

### 排查手法

```bash
# 真实错误在这里（lastError 字段）
curl -s http://127.0.0.1:3210/api/skills | python -c "import json,sys; [print(s['id'], s.get('lastError')) for s in json.load(sys.stdin)['skills'] if s.get('lastError')]"
```

看到 `lastError` 非空 → 说明这个技能**正跑着旧实例**，改的代码一个都没生效。

### 因此代码里的一条纪律

**入口模块的顶层不要读子模块的新字段。** 需要就用惰性函数包起来
（本技能的 `shopTable()` 就是这么做的）—— 这样即使新旧搭配对不上，
也只是某个工具报错，而不是整个技能加载失败、且静默。

## 十二、⚠️ 写测试时必读：DATA_DIR 会决定你写到哪

`src/config.js` 里是：

```js
export const DATA_DIR = process.env.QQ_AGENT_DATA_DIR || path.join(ROOT, `data${profileSuffix()}`);
```

**`QQ_AGENT_DATA_DIR` 是「数据目录本身」，不是「它的父目录」。**

- ❌ `QQ_AGENT_DATA_DIR=.../resources/app` → 数据写到 `resources/app/`（**技能目录里会长出 `chats/`**）
- ✅ `QQ_AGENT_DATA_DIR=.../Temp/whale-sandbox` → 写进一个独立沙箱

写这个技能的测试时踩过：把变量设成 `resources/app`，于是测试存档一路写进了
`skills/travel-whale/chats/`，还被热重载监听到（日志里刷 `检测到变化：travel-whale`）。
更坑的是**清理脚本清的是 `resources/app/data`，根本不是那个目录**，所以残留一直累积、
测试结果看着像"重复发片"。

**两条纪律**：
1. 测试用**独立的临时目录**，别指向项目内任何路径；
2. 清理测试数据按**精确文件名**删，不要用 `includes('12345678')` 这种模糊匹配 ——
   那会把真身存档和备份一起删掉。

## 十三、已知限制

- **货架补货是"整批清空重来"**：到点后所有商品一起补满，没有逐件错峰；
- **明信片图不参与成本统计**：它走的是 `image.generate` 能力，不计入核心的
  用量/成本页（技能自己的存档里能数出张数）；
- **说明图依赖 Electron**：纯 Node 环境下 `renderPng` 会抛错，此时自动降级为文字版
  （这条有兜底，不影响功能）；
- **自由路径的 20% 不可控**：可能挑到冷门地方。已有"大区校验 + 搜索没玩头就回落池子"
  两道兜底，但仍可能比池子路径平淡。
