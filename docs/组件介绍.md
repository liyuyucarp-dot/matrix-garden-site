# 组件介绍

> 16 个组件，按"她的一天"顺序排：**先有身体 → 再有心情 → 再有事可做 → 再有想说的 → 再有人看见 → 再有人教她**。

---

## 一、技能（她会做的"事"）

### 1. 矩阵庭院 `skills\travel-whale`

**她住在里面。** 自己出门旅行、寄明信片回来、带特产、攒钱买设施、种菜。

- **核心设置（必填）**：`homeChatKey`（哪个群是"家"）、`cardTargets`（明信片投给谁）
- **她的自主行为**：自己决定买什么（`autoSpend`）、自己收菜补种（`autoTend`）、
  自己判断想不想出门（**出门前会先问自己一句**，不想走就把下次顺延）
- **明信片**：每趟按口粮档位抽 1~4 张，途中寄 + 到家一张；配图由生图模型出
- **稀有特产图**：第一次带回时生成，随「我回来啦」的归家播报一起发出；图鉴页顶部有图墙，
  点名「看图鉴里的 某某」可直接看那一张原图
- **旅伴**：7 位，各有人设卡（在 `personas.json`，改完即时生效，不用重启）
- **世界观数据**：`data\` 目录（地区表 / 世界书 / 语气档案…）——**v1.0.0 漏带了，v2 已补齐**，
  缺了它旅行系统起不来
- **依赖**：核心补丁里的 services 钩子（见下）；接 `sleep-mood` 才有"旅行时的心情/身体"

### 2. 空间日记线（v2.3.0 起并入 `skills\qzone`）

> **2026-10-27 合并**：原 `skills\qqzone`（长文线）已并入 `skills\qzone`，用设置项
> 「社交线 / 日记线」两个开关分别控制。工具名相应变为 `qzone__collect_diary` / `qzone__post_diary`
> （原 `qqzone__collect_diary` / `qqzone__post_diary`）。下文的职责描述仍然有效，位置看 `components/skills/qzone/lib/diary.js`。

**每晚写一篇长日记，排版成图发出去。** 素材按比例拼：**一半旅行 / 四分之一B站 / 四分之一群聊**
（没出门则一半给庭院）。

- 到点自动写（默认 23:00），也能手动叫它写
- 配图从当天寄回的明信片里挑；有「长文排版图」技能时渲染成 PNG 再发（按天限频）
- 只有 2 个工具：**收集日记素材**、**发日记说说**
- **依赖**：`bili-whale`（B站那 1/4 的素材；没有就静默少这一块）

### 3. 空间动态 `skills\qzone`（社交线）

**她在空间里的日常社交**：发短说说（可带聊天里的图）、刷好友动态、读评论、
给别人的说说点赞/评论、**回复别人留给她自己的评论**；
有人评论她的说说时她会自动知道，并且会定时巡视好友动态把新动态送到眼前。

- 6 个工具：发说说 / 刷好友动态 / 读说说评论 / 点赞 / 评论 / 回复评论
- 所有读写都走 bot 自己的登录态

> **★ 这两个是互补的，不是替代 —— 两个都该装、都能同时开。**
> `qqzone` 只做日记那条长文线，`qzone` 管社交那条线；它们的工具和职责完全不重叠。
> （`qqzone` 的技能描述里就写着："发说说/刷动态/点赞/评论由 skills/qzone 负责，本技能只留日记线"。）
> 互通的地方只有一处：日记发出去之后，**别人在那条说说下的评论由 `qzone` 去读和回**。

### 4. 庭院与旅程 `skills\courtyard-map`（★ v2 新增，可视化面板）

**把庭院画进一张图，让你不用翻存档就能看见她的生活。**

- **地图页**：世界分区底图 + 她当前所在的金色信标（呼吸动画）+ 到访过的城市节点 +
  星轨航线（按出发时间串起来的虚线弧）+ 异世界区（未揭示的显示 ？？？）
- **庭院页**：池塘 / 钱袋（TOKEN）/ 衣柜 / 称号与成就值 / 庭院设施等级 / 纪念品墙 / 近况时间线
- **旅伴页**：**全量名册**——7 位旅伴全部显示，emoji 严格对齐庭院本体；
  未解锁的标【未解锁】并禁入；已解锁的显示实时状态（在庭院 / 随行中 / 自己出门了+在哪）
  - **★ v2.2.6 立绘档案**：卡片可点开，左立绘（240×300 压小，点一下看原图大图）+ 右侧能力（特性 / 倍数 / 每日 TOKEN）、
    同行（累计趟数 · 带路去过几个异世界 · 世界与城市芯片）、**技能牌**（已学亮绿；未学灰牌并显示差什么）、来历与性格
- **足迹页**（v2.2.6 新增）：按旅伴分组，列出**和谁去过哪个世界的哪座城、各几趟**（只计异世界同行）
- **相册页**：明信片灯箱（有图直出）
- **数据**：30 秒快照自动刷新；对 travel-whale **只读、零侵入**（不改它一行代码）
- **入口**：设置 → 插件 → 庭院与旅程 → 「打开庭院与旅程」
- **依赖**：`skills\travel-whale`（只读其存档、`state.js` 名册、`regions.json` 世界表）——本包已带

## 二、插件（她的"身体和脑子"）

### 5. 好感核心 `plugins\favor-core`

**她对你、对群友的好感值与关系状态。** 好感会随互动变化，并影响她说话的距离感。

- 是别的组件的基础：`sleep-mood` 会读它来决定"对谁能撒泼、对谁要客气"
- **依赖**：核心补丁 `src\memory-people.js` + `src\memory-audit.js`（静态 import，缺文件 = 起不来）

### 6. 生活系统 `plugins\life-system`

**世界设定与日历。** 给旅行提供"这个世界现在什么局势"（酒馆关了、城里戒严…），
让明信片和日记不会永远是太平年月。

- **依赖**：核心补丁 `src\half-life.js`（静态 import，缺文件 = 起不来）

### 7. 心情与元气 `plugins\sleep-mood`（★ v2.2 精简重构）

**两条轴，取代原来的 11 维碎数值。**

- **元气轴（0~100）**：清醒时**绝不自然消耗**，只由旅途战斗/奇遇、吃特产、庭院慢生活、睡眠/泡澡驱动；
  低于「微倦线」（默认 45）语气放软，低于「困倦线」（默认 20）更短更困。
- **具身情境心境**：最多 2 个活跃心境 Tag，每个都带**具体因果**（`why`）和过期时间 ——
  「因为主人今天夸了她」而不是「开心 37 分」。仍然按原结构投影出 `mood.json`，
  所以 mind-wish / autobiography / 庭院面板读到的字段一个不少。
- **单时钟**：删掉独立的室内作息表，她"在干什么"100% 由旅行鲸鱼的在途 / 庭院状态接管，
  不再出现"人在罗弗敦却掷骰子去打游戏"的精神分裂。
- **睡眠**：命令睡眠（`/睡觉`、`/起床`）+ 自然睡眠（她自己说"我去睡了"）。睡着时入站消息照常存档、
  不送模型（零 token），醒来补看。
- **v2.2 砍掉的**：生命值 / 零血失忆、好感联动 35 项概率骰子、疲劳连锁 A/B/C、低血、归零清库、
  吵架加速、抑郁、冷落惩罚，以及 5 个随之消失的工具（`hp_status`/`hp_adjust`/`hp_wipe_plan`/`hp_wipe_restore`/`favor_link_status`）。
- **设置 40 项**，分五组排：基础 / 睡眠·吵醒 / 身体·元气 / 旅行同步 / 语气联动（设置 → 插件 → sleep-mood）。
- **数据兼容（重要）**：旧 `mood.json` 会自动迁移成 vitality 口径，写盘时 `vitality` 与 `fatigue`
  **双向同步维护**；`self-state.json` 新旧两种结构（嵌套 `{self:{…}}` / 平铺）都能读，
  写回统一用旧结构 —— **回滚到 1.x 也不会读到脏数据**。旅行事件光标文件与旧版共用，不会重放历史事件。
- **必填**：`travelGroups`

### 8. 主动私信 `plugins\silence-ping`

**冷场时她自己找你说话。** 每 15~30 分钟醒一次，挑一个"最久没聊"的私聊对象，问自己"要不要说句话"。

- **只发私信，群聊一律不管**（代码级硬过滤）
- **念想模式**：不是"必须发一条"，而是"你现在想起了这个人" —— **想起来了但没话是正常状态**
- **v2**：念想话题之外，新增"旅行事件"类低权重话头（在哪、和谁、干什么）
- 有「等回复」保护：你还没回上一条，她不会追第二句
- **必填**：`dryRun` 关掉才会真发（默认开）

### 9. 念想 `plugins\mind-wish`

**她自己惦记着的事。** 从三路长出来：情绪变化、B站见闻、庭院经历 → 算强度、会衰减、注入【你此刻惦记的事】。

- 上限 6 条，每次只注入最强的 3 条
- **每天最多新增 3 条**（防爆闸，因为庭院的活动时钟是 20 分钟一条、44 条/天）
- **情绪只影响排序，不影响"要不要说"** —— 说出口是 `silence-ping` 的事
- **v2**：素材读取带缓存，同一批不再反复解析
- **依赖**：`sleep-mood`（读情绪）、`bili-whale`（读见闻）；只读不写

### 10. 思考分级 `plugins\think-gate`

**短句就不用想了。** 「嗯」「哈哈」「在吗」这类消息免掉模型的思考，省 reasoning token、降低首字延迟。

- 判据：媒体 / 超过24字 / 疑问 / 任务 / 判断 / 冲突 / 数字 → **照常思考**；其余免思考
- 顺带好处：免思考就不会产生 `reasoning_content`，也就不会撞上 DeepSeek 那个
  `reasoning_content must be passed back` 的 400
- **拿不准一律照常思考**（想错的代价比省下的 token 大）

### 11. B站 `plugins\bili-whale`

**她刷B站。** 看视频、深读、写分享语、写日记、记下看过的。

- **给别处供料**：`qqzone` 的日记、`mind-wish` 的念想都读它的记录
- 需要自己配：账号、看视频的时间段、视觉/听觉模型通道
- **不配也能装**，只是不会有新素材进来

### 12. 庭院体检 `skills\courtyard-doctor`（★ v2 新增，诊断工具）

**对机器人说「庭院体检」，她会把整个矩阵庭院查一遍并出报告。**

- 查什么：核心补丁在位情况、家/主人配置一致性、可信权限、禁言与风控链路、
  外部凭据存在性（只报"已配置/长度"，**任何 Key 的值一律不进输出**）、昨夜日记是否落盘
- 只读、不联网、不写文件——体检本身绝不成为新的故障源
- 虽然住在 `skills\` 目录，但它是**给人用的诊断工具**，不参与"她的一天"

### 13. 庭院总线 `plugins\courtyard-bus`（★ v2.1 新增，事件总线试点）

**组件间的实时神经。** publish / subscribe 进程内事件——sleep-mood 情绪一位移，
mind-wish 当场就知道（不再等最长 10 分钟的轮询）。

- 当前已通：`mood:state.shifted` → mind-wish 即时吸收；后续事件按《03.md》词表逐条接入
- **零依赖、零 fs、重启即清**——总线挂了各组件自动退回轮询，功能不受损

### 14. 自传体记忆 `plugins\autobiography`（★ v2.2 重构：睡前沉淀进知识库）

**她睡下的时候，把这一天收进自己的回忆。** 庭院活动 / 明信片 / B站日记 / 情绪波动 / 好感变化
→ 提炼成一句第一人称的回忆 → **直接写进知识库**（`data\knowledge-base\learned\她的回忆.md`，按天分小节）。
于是这条回忆**可以被检索、可以被编辑、也可以被她自己在聊天里调 `kb_search` 想起来**。

- **触发时机**：**命令睡眠（`/睡觉`）随时算**；**自然睡眠只在夜里算**（默认 21:00–06:00，两端都可配）
  —— 午后小憩/午睡不会被当成"睡前"，也不会占掉当天的机会
- **一天最多一条**：`nodes.json` 按日期去重 + 内存标记双保险
- **空素材不落节点、不调模型**：那天确实没素材就只记一行日志（不硬编、不产生虚构回忆）
- **不再注入提示词**：回忆改走知识库检索，不再每天往提示词里塞一段变长文本（不扰动前缀缓存）
- LLM 提炼失败自动走模板兜底；凭据一律不入库
- **依赖**：只读 travel-whale / bili-whale / sleep-mood / favor-core 的数据；
  写库走软依赖 `knowledge.write` —— 知识库没装或没开时只留 `nodes.json` 台账，**巩固本身不受影响**

### 15. 知识库 `plugins\knowledge-base`（★ v2.1 新增）

**丢个 txt/md 进 `data\knowledge-base\`，机器人就学会了。** 回答前先翻本地知识库，
翻不到才上网搜，搜到的自动存进 learned/；同主题合并、重要度参与检索排序。

- 三个写入方：① 你自己放资料；② `learning-loop` 自动巩固群共识/主人嘱咐；
  ③ **`autobiography` 每天睡前把回忆沉淀进来**（`learned\她的回忆.md`）
- 对外三个能力：`knowledge.search` / `knowledge.write` / `knowledge.update`
  —— 别的组件写库统一走 `knowledge.write`（软依赖，知识库关了就不写、也不报错）

### 16. 学习与反馈闭环 `plugins\learning-loop`（★ v2.1 新增）

**常态化自主学习**：每轮扫描消息识别纠正/确认/「记一下」信号；检索无命中时把查询
记成待学条目；同一条内容 ≥2 个信源、或同一人 ≥2 个日期重复说过、或主人明确要求记——
满足任一即自动写进知识库。

> 13~16 与 15 是**一组**：learning-loop 产出进 knowledge-base，一起装、一起开。

## 四、它们之间怎么连

```
favor-core ──┐
             ├→ sleep-mood（心情/身体）──┬→ travel-whale（旅行时的心情）
life-system ─┘                            └→ mind-wish（情绪 → 念想）
                                                  ↑
bili-whale ───────────────────────────────────────┤（见闻 → 念想）
                                                  ↑
travel-whale（庭院经历）───────────────────────────┘
      │
      └─（存档/名册/世界表，只读）──→ courtyard-map（庭院与旅程面板）
                                       courtyard-doctor（体检报告）

mind-wish ──（她惦记着谁/什么）──→ 她自己决定要不要说
                                        ↑
silence-ping ──（冷场时问她一句）────────┘
                                        ↑
qqzone ──（把这一天写成日记）────────────┘
```

**关键设计（贯穿全部组件）**：闸门只决定"**有没有机会**"，不决定"**她说什么**"。
所以你会看到很多地方写着"你自己定""不想也行""想起来了但没话是正常状态"——那不是客套话，是机制的边界。
