# 更新日志 · V3.0.0（组件重构）—— `qqzone` 并入 `qzone`

> 2026-10-27 ｜ 包版本 `3.0.0-dev.1`（**仅仓库内，未发版**）｜ 组件：`qzone 1.5.1 → 2.3.0`，`qqzone 2.4.0` → **并入**
> 本条是**结构性变更**：组件数 **16 → 15**，技能数 **5 → 4**。

---

## 一、为什么合并

审计与实测都指向同一件事：`qzone`（社交线，6 个工具）与 `qqzone`（日记线，2 个工具）是**两条业务线共享同一套底层**：

| 重复项 | 体量 | 说明 |
|---|---|---|
| Cookie 链路 | 106 行 | `acquireCookies` / `fetchCookiesViaOnebot` / `parseCookiesField` / `cookieHeader` |
| SnowLuma 适配 | 80 行 | `readSnowHttpServices` / `ownHttpPorts` / `snowConfigCandidates` |
| 布局与数据目录 | 66 行 | `findAppRoot` / `dataDirCandidates` / `dataDir` |
| 协议与小工具 | 46 行 | `gtk` / `imageKindOf` / `sanitizeText` 等 |
| 高度相似 | ~135 行 | `jsLiteralToJson`(91%) / `uploadQzoneImage`(88%) / `recordAct`(98%) |

合计 **≈433 行**，且都是"最容易出安全事故"的部分（Cookie、token 扫描、上传、风控）。
同一处风控要改两遍、同一个 cookie bug 要修两次 —— 这就是合并的直接理由。

## 二、结构变化

```
components/skills/qzone/
  skill.json            8 个工具 / 40 项设置（社交 20 + 日记 17 + 共享 3）
  index.js              装配层（93 行）：设置合并与迁移 / 按开关装配两条线 / 统一生命周期
  lib/social.js         社交线（原 skills/qzone/index.js），2169 行
  lib/diary.js          日记线（原 skills/qqzone/index.js），2459 行
components/skills/qqzone/   ← **已删除**
```

**装配层的做法**：宿主只给一个 `config()`（整技能的设置），但两条线的设置键**完全不相交**，
所以 `index.js` 把合并后的设置**切两份视图**传给两个分片 ——
`lib/social.js` / `lib/diary.js` 里的代码**一行都没改**，也不用知道对方存在。

## 三、行为变化（要记住的三条）

| # | 变化 | 影响 | 处理 |
|---|---|---|---|
| 1 | **工具名变更**：`qqzone__collect_diary` → `qzone__collect_diary`，`qqzone__post_diary` → `qzone__post_diary` | 模型若按旧名调用会失败 | 工具描述里已写明新名；如果你有自定义提示词/工作流引用了旧名，请替换 |
| 2 | **设置合并**：原来两套 `enabled`，现在一个总开关 `enabled` + 两个线开关 `socialEnabled` / `diaryEnabled` | 旧配置的 `enabled:false` 语义是"整条线关"，现在映射到对应线的开关 | 见第四节迁移表 |
| 3 | **默认值**：技能整体 `enabledByDefault: false`（与两线一致），但 `socialEnabled` / `diaryEnabled` 默认 **true** | 以前要把两个技能都打开才两条线都跑，现在**开一个技能即可，两条线默认都开** | 想只跑社交线 → 关 `diaryEnabled`，反之亦然 |

> 未变的：6 个社交工具名、全部设置键名（除 `enabled` 拆成三键）、数据文件位置
> （`data/skills/qzone/` 与 `data/skills/qqzone/` 各自保留，**不搬家、不合并存档**）。

## 四、升级与回滚

### 升级（已装过 v2.2.x 的机器）

1. 退出宿主；
2. 覆盖 `skills/qzone`（新增 `lib/` 目录）；
3. **删掉** `skills/qqzone`（否则两条线会同时注册日记工具，出现重复工具）；
4. 重启。设置面板里会看到「社交线 / 日记线」两个开关，旧配置会自动迁移（`settingsVersion: 3`，幂等）。

### 回滚

```bash
git revert <本次提交>      # 或整体 tag 回退
```
存档不需要动：`data/skills/qzone/` 与 `data/skills/qqzone/` 都还在，回滚后照旧读得到。

其中**闸3 新增了工具断言**：只要 manifest 声明了工具、而 `setup()` 一个都没注册就判失败 ——
这正是合并时最容易犯的错（比如条件判断写错导致整条线不装配）。本次 qzone 注册 **8/8**：
`post_mood, list_feeds, read_comments, like_feed, comment_feed, reply_comment, collect_diary, post_diary`。

> ⚠️ 静态探针**不能**验证真实 Qzone 行为（不出网、不连 OneBot）。真实环境仍需按《安装说明》的验收清单手工跑一遍：
> 发一条说说 → 刷动态 → 读评论 → 点赞 → 评论 → 回一条；再用「收集日记素材 / 发日记说说」各跑一次。
