## 一、【高】包里有两份 reply-rescue，手动安装会装到没修 BUG-01 的旧版

### 现象

v2.2.0 包里同时存在：

| 位置 | 大小 | 状态 |
|---|---|---|
| `核心补丁\files\src\reply-rescue.js` | 12,617 B | ✅ 含 10-25 的 BUG-01 修复（`runOutboundGuards({ text, trigger, messages }, log)` 传了 `messages`） |
| `核心补丁\src\reply-rescue.js` | 12,331 B | ❌ **旧版**，漏传 `messages` |

`apply-core-patch.ps1` 读的是 `files\`，所以**跑脚本是安全的**；但 `安装说明.md` 第二节「手动安装」写的是
"把 `核心补丁\src\reply-rescue.js` → ...\src\reply-rescue.js"。**用户按文档手拷，装进去的就是漏修的那版**：
出站守卫表为空时 `context.messages` 是 `undefined`，救援网在 `.length` 上直接抛 TypeError —— 也就是
"模型把工具调用写成残骸时，本该救回来的那条回复救不回来"。

顺带同一节还有 3 行（`manager.js` / `plugin-loader.js` / `app.js`）指向 `核心补丁\src\` 下**根本不存在的文件**
（这 3 件是锚点插入，包里只有 `snippets\`），手拷到那一步只会得到"文件不存在"。

另有一个纯冗余：包根目录躺着一份 `src\`（`app.js` 339 KB + `reply-rescue.js` + `skills\manager.js`，共约 393 KB），
`install.ps1` 根本不读它 —— 但"包里有个 src\"这件事本身就会诱导人整目录覆盖进宿主。

### 做法

1. **删掉包根 `src\`**（3 个文件，约 393 KB）；
2. **删掉 `核心补丁\src\`**（`prompt.js` 重复 + 旧版 `reply-rescue.js`）；
3. **重写 `安装说明.md` 第二节第 3 步**：路径全部改为 `核心补丁\files\...`，并明确区分
   「6 件整文件覆盖」与「3 件锚点插入（只能跑脚本 / 照 `手动接线片段.md` 手插）」。

现在全包**只有一份**补丁源文件：`核心补丁\files\`。

### 怎么验

- `apply-core-patch.ps1` 只 `Join-Path $Here ("files\" + $e.path)`，不碰包根 `src\`；
- `install.ps1` 只复制 `skills\` 与 `plugins\`；
- 删完后包内 `reply-rescue.js` 只剩 1 份，大小 12,617 B。

### 代价

无。两份删掉的都是**没有任何代码引用**的副本（备份在打包机的 `%TEMP%\pkg-v2\_removed_from_pkg\`，
真要找回也能从 v2.2.0 的 zip 里取）。

## 二、【中】面板好感图谱：条形宽度除以 40，谁看着都像不认识

### 现象

`skills\courtyard-map\panel\map.js` 原来这么算宽度：

```js
Math.round(Math.abs(f.favor) / 40)   // ← 0~4000 的老口径
```

而 favor-core 的 `favor` **本来就是 0~100**（本机 220 份档案实测 min 23 / max 100）。
后果：好感 100 的群友条形宽度 = `Math.round(2.5)` = **3%**，好感 70 的 = **2%** —— 整页好感图谱几乎全空。

同时 `courtyard-map\index.js` 的 `readVitals()` 还在读 `depress` / `neglect` / `spunk`，
这三个在 sleep-mood v2 里已经是**恒 0 的兼容桩**，于是面板上常驻「抑郁 0 / 忽视 0 / 活力 0」三根空条 ——
看起来像"她抑郁到底、毫无活力"，纯属误导。

### 做法

- 好感条：直接用 `Math.round(Math.abs(f.favor))`（0~100 即百分比）；
- `readVitals()` 改为返回 `vitality`（元气，真实身体轴）+ `fatigue` + `mood` / `satisfaction` / `rage`，
  不再返回三个恒 0 桩；
- 面板展示项改为：心情 / 满足 / **元气** / 愤怒；**没有 vitality 的老快照自动回退显示疲劳**，行为等价。

### 怎么验

对当前存档跑一遍 `readVitals()`，返回的是
`{vitality: 94, fatigue: 6, mood: 93, satisfaction: 85, rage: 0}`（数值随时间变，重点是
**有 `vitality`、不再有 `depress` / `spunk` / `neglect` 三个键**）。
好感图谱按 100 分制铺满：好感 100 的群友 = 100% 宽，70 的 = 70%（旧版分别是 3% 和 2%）。

## 三、【中】庭院体检：写死检查包外插件，反而漏了本包真要权限的组件

### 现象

`skills\courtyard-doctor\index.js` 原来写死：

```js
const needTrust = ['mind-wish', 'bili-whale', 'sticker', 'desktop-pet', 'courtyard-doctor'];
```

两个问题：

1. **误报**：`sticker` / `desktop-pet` **不在本包里**。新用户装完第一次体检，必得两条
   「⚠ sticker 不在 trustedPlugins」「⚠ desktop-pet 不在 trustedPlugins」——人家根本没装桌面宠物。
   （`组件状态` 那一节也无条件打印 sticker / desktop-pet 两行，同样是幽灵。）
2. **漏检**：本包真正 `import node:fs`、会被宿主能力闸拦的组件一个都没查 ——
   `sleep-mood`、`autobiography`、`knowledge-base`、`learning-loop`、`life-system`、`silence-ping`、
   `courtyard-map`、`travel-whale`、`qqzone`、`qzone`。
   真被闸门拦下时，报告反而是绿的。

### 做法

改成「**装了才查** + 覆盖全部需要文件权限的组件」：

```js
const TRUST_CANDIDATES = [
  ['plugins','mind-wish'], ['plugins','bili-whale'], ['plugins','sleep-mood'],
  ['plugins','silence-ping'], ['plugins','life-system'], ['plugins','autobiography'],
  ['plugins','knowledge-base'], ['plugins','learning-loop'],
  ['plugins','sticker'], ['plugins','desktop-pet'],        // 宿主自带，装了就查
  ['skills','courtyard-doctor'], ['skills','courtyard-map'],
  ['skills','travel-whale'], ['skills','qqzone'], ['skills','qzone']
];
// 判据 = 目录是否存在（不是配置里有没有），所以"只装了其中几个"的机器也准确
```

`组件状态` 里的 sticker / desktop-pet 两行同样加了 `installed()` 前置条件。

### 怎么验

按同一份候选表把本机走了一遍：**15 个候选全部已装、全部在 trustedPlugins 里** → 体检会输出
`✓ trustedPlugins 覆盖完整（已装 15 个需文件权限的组件，全在列）`；
在缺 `sticker` / `desktop-pet` 的机器上，那两行**不再出现**（也不再计入"已装 N 个"）。

### 代价

多 15 次 `fs.existsSync`，毫秒级；体检本来就是手动触发的只读诊断。

## 四、【低】自传素材重复：同一句心情原因被收了两遍

### 现象

sleep-mood v2 的 `normalizeAndProject()` 会把一个 `tone:'good'` 的心境 Tag **同时投影进 `excited` 和 `happy`**
（同一个 `why`、同一个 `at`）。而 `autobiography` 的 `collectToday()` 遍历 `Object.values(mood.moods)` 时没去重
→ 同一条原因在当天素材里出现两次 → 提炼出的回忆会重复念叨同一件事。

顺带一处文案漂移：节流常量 `RETRY_MS` 早就从 1 小时改成 20 分钟，但跳过原因是写死的
`'距上次尝试不足 1 小时'`。

### 做法

- `collectToday()` 的情绪采集改成：**moods 与 activeTags 两个来源都收**，用 `Set` 按 `why`（前 60 字）去重
  —— moods 覆盖"已结束"的、activeTags 覆盖"正挂着"的，两边都不丢；
- 跳过原因改成按常量算：`` `距上次尝试不足 ${Math.round(RETRY_MS / 60000)} 分钟` ``，以后不会再漂。

## 五、【低】`mood_adjust` 手动挂心境没广播总线

### 现象

旅途事件走 `applyTravelEventMood()` 会 `publish('mood:state.shifted')`，mind-wish 即时吸收；
但模型在对话里调 `mood_adjust` 挂上一个强心境时，只 `pushMoodTag()` + `publishDashboard()`，
**漏了总线广播** —— 同一个状态变化，两条路径的口子不一致：旅途是实时的、对话要等 10 分钟轮询。

### 做法

`mood_adjust` 挂载 Tag 成功后补一次广播（`kind:'manual-adjust'`），格式与旅途事件那条完全一致：

```js
api?.capability?.('courtyard.bus')?.publish?.('mood:state.shifted', {
  kind: 'manual-adjust', tag: tagName, vitalityDelta: 0, why: reason, at: now
});
```

`catch` 吞掉异常 —— 总线没装/没开时行为与以前完全一样（各组件退回轮询）。

### 代价

多一次进程内同步调用（几微秒）。mind-wish 的处理器是幂等的（收到就重读 `mood.json`），不会重复计分。
