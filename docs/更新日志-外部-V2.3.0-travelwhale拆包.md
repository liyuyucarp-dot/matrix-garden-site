## 一、为什么必须先拆巨石，再脱离绑定

原 `skills/travel-whale/index.js` 单文件塞入了 **8,351 行代码、188 个顶层函数、271 个顶层声明**，同时混杂了：

- 心情事件推送、异世界战斗掷骰、属地随机事件

- 世界状态（Phases）7 天轮换、地区可见性/解锁判定、庭院慢生活、`life-system` 世界书同步
- 口粮/护身符消耗、异世界穿越判定、主行程出发（`depart`）
- 「家」与多群扇出广播（BROADCAST）、面板防刷屏
- 明信片送达账本、区域服装挑拣、途中/归家寄卡、稀有特产配图、归来结算（`settleTrip`）
- 庭院大合照、`side-wish` 跨宿主出门申请、闲置伙伴自游出行/结算
- 自主意愿（`considerDepart`）、无聊值、自动花销（`autoSpend`）、自动收菜补种（`autoTend`）、自动邀约
- 后台主时钟（`tick` / `startTicker`）
- 商店货架表、加急明信片、相册按趟分组、菜单图数据装配
- 特产图鉴查找、吃/送犹豫闸门、菜地种植/收获/收成配图
- 23 个 `whale_*` 工具注册、生命周期与提示词段组装

如果不先按职责边界拆开，下一步做“角色/世界观配置化”时，改动任何一个设定都会牵连 8000 行上下文。

## 三、关键工程防坑设计

1. **彻底消除 TDZ（暂时性死区）与循环绑定隐患**：
   - 原单文件里 `SELF_DIR` 声明在第 2170 行，导致前面的函数必须写注释提醒“不能在顶层引用 `SELF_DIR`”。拆分后，`SELF_DIR` 统一由 `core/world-sync.js` 导出（基于 `import.meta.url` 向上解析一级回到 `skills/travel-whale` 根目录），`personas.json`、`events.json`、`regions.json`、`worldbooks.json` 全部指向准确的技能根目录。
2. **可变运行时状态收敛至 `RT` 单一容器**：
   - 原单文件顶层的 `let cfg / log / services / capability / timer / apiRef / cancelServices` 已收敛进 `core/runtime-deps.js` 的 `RT` 对象，并提供 `setCfg` / `setLog` / `setServices` / `setCapability`。无论是宿主 `setup(api)` 注入，还是离线单测通过 `internals.setCfg` / `internals.setServices` 注入，15 个子模块实时共享同一份引用，绝不出现 ESM 跨模块变量拷贝失步。
3. **100% 向后兼容 `courtyard-map` 与全部离线探针**：
   - `skills/courtyard-map/index.js` 原有的 `import { internals as TW_INTERNALS } from '../../skills/travel-whale/index.js'` 零修改即可直接工作；
   - 原 `index.js` 的 39 个顶层命名导出与 142 个 `internals` 属性一个不少。
