## 一、庭院总线：从"只有一条线"到"词表接通三对"

### 问题（实测发现，比预想的更彻底）

`plugins/sleep-mood/index.js` 早就写好了两条订阅：

```js
bus.subscribe('whale:trip.event',     () => applyTravelEventMood(Date.now()));
bus.subscribe('whale:souvenir.eaten', () => applyTravelEventMood(Date.now()));
```

但 `skills/travel-whale/` 里 **一次 `publish` 都没有**（全目录 grep `courtyard.bus` = 0 命中）。
也就是说这两条订阅**从来没被触发过**，旅途事件仍然要等 sleep-mood 下一轮 60 秒心跳才结算成元气/心境。
同理，没有 `sleep:state.changed` 这个主题 —— `autobiography` 只能靠轮询知道"她睡了"。

### 做法

**① `travel-whale` 发布（唯一漏斗 `pushMoodEvent()`，一处改动覆盖 16 种事件）**

```js
const topic = k === 'souvenir-eat' ? 'whale:souvenir.eaten' : 'whale:trip.event';
setTimeout(() => capability('courtyard.bus')?.publish?.(topic, payload), 0);
```

为什么延到下一个宏任务：调用方是在 `pushMoodEvent()` **之后**才 `S.saveState(state)`（同步写盘），
而订阅方读的是**文件** —— 立刻 publish 会让它读到还没落盘的旧存档，白跑一趟。
`setTimeout(0)` 排在整个同步调用栈之后，正好落在存盘之后。
万一某条路径是先 `await` 再存盘，订阅方也只是"这轮没看到"，**它自己的 60 秒轮询仍是兜底**（游标按 `(at,id)` 去重，重复交付无害）。

**② `sleep-mood` 广播 `sleep:state.changed`**

三态（`awake` / `command` / `natural`）**边沿触发**：只在真的变化时发一次，不是每个 tick 都刷。
发起点有四个：心跳 tick（兜底）、入站闸门识别到 `/睡觉`、`sleep_control` 工具、`wakeUp()` 醒来。

**③ `autobiography` 订阅**

收到 `command` 立即沉淀；收到 `natural` 仍要过夜间门槛（与轮询同一判据，午后小憩不算）。
真正的重活丢到 `setTimeout(0)` —— `publish` 是在 sleep-mood 的**入站闸门**里同步调用的，
而本函数要同步读 `nodes.json` 与各组件存档，不能占着别人的热路径。
**轮询保留**（这是 bus 的降级红线：总线不在就退回 60 秒一跳，行为与以前一致）。

### 怎么验

假宿主树 + 真 courtyard-bus 模块联调：

```
订阅情况: {"topics":[{"topic":"sleep:state.changed","subscribers":1}], ...}
publish('sleep:state.changed', {state:'command'})  →  400ms 后：
  nodes = 1 条｜trigger=command-sleep
  kb 调用: 1 次 {"title":"她的回忆", ...}
✅ 总线即时触发成功（未等 60s 轮询）

publish('sleep:state.changed', {state:'natural'}) @ 15:00（非夜间）
  → nodes=0，kb=0  ✅ 小憩不沉淀
```

### 代价

- 每轮旅行事件多一个 `setTimeout(0)` 与一次进程内同步调用（微秒级）；
- sleep-mood 的广播只在状态变化时发生，稳态下零开销；
- 订阅方若崩，`publish` 内部逐订阅者 catch，不会影响发布方（总线自己的契约）。

## 二、面板与体检：跟上 v2 的双轴模型

### `courtyard-map`（`index.js` + `panel/map.js` + `map.css`）

- **「心情与身体」卡**：v1 的 7 项里 `抑郁 / 忽视 / 活力` 在 v2 恒为 0，已去掉；
  现在展示 **心情 / 满足 / ⚡元气 / 愤怒**（没有 `vitality` 的老快照自动回退显示疲劳）。
- **新增具身情境 Tag 区**：卡片底部列出当前活跃的 1~2 个 Tag，带 **原因** 与 **剩余分钟**，
  坏心情标红、mixed 标黄 —— 于是"她为什么是这个心情、还能热乎多久"在面板上一眼可见。
- 快照里 `vitals.tags` 由 `readVitals()` 从 `mood.json` 的 `activeTags` 投影（`tag / why / tone / level / leftMin`）。
- ⚠️ `hasVitals` 判定同步修正：`tags` 是数组，不能因为"数组不是 null"就认为有数值（否则会渲染一张空卡）。

### `courtyard-doctor`

新增 5 个只读体检项（**装了才查**，与 sticker/desktop-pet 同一原则）：

| 组件 | 看什么 |
|---|---|
| `courtyard-bus` | 直接调 `describe()`：已发布/投递计数 + **每个 topic 的订阅者数**（订阅者 0 = 词表只接了一半，这是"事件到底通没通"的唯一实证） |
| `autobiography` | `nodes.json` 台账条数 + 最近日期 + **知识库沉淀文件是否已生成** |
| `knowledge-base` | `learned/` 篇数 + 索引构建时间与段数 + 注入模式 |
| `learning-loop` | 启用状态 |
| `courtyard-map` | 面板文件是否在位 |

> 上一版（v2.2.1）已经把 `trustedPlugins` 校验扩到 15 个候选并改成"装了才查"，
> 这一版补的是**状态可见性**：以前只能从信任名单侧面推断，现在能直接看到"总线通没通、回忆落没落地"。
