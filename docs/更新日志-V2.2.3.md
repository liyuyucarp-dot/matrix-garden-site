## 一、问题：kp 那张卡上的「⚠ 有警告」是误报

界面上的原文：

> ⚠ kp 注册了工具但没有提示词片段（promptSections/prompt）：模型能"调"到它，但不知道什么时候该用

**判据确实成立，但结论是错的。** 来源 `src\plugin-loader.js` 的 `lintKindPlacement()`：

```js
if (kind === 'skill' && hasTools && !manifest.prompt && typeof promptSections !== 'function') {
```

kp 三条全中（`skills\kp` 目录、注册了 6+ 个 `kp__*` 工具、`skill.json` 无 `prompt` 键、
`index.js` 不导出 `promptSections`）。**但它的引导全在 `hooks['before-llm-messages']` 里**：
`index.js:1120` 那段一共 7 处 `stableParts.push`，包括整套 KP 系统提示词、
`legacy.userPromptParts()` 的 stable/volatile 两段，以及五段手写规矩
（战斗怎么做 / 法术位怎么记 / 队伍卡册什么时候发 / NPC 认知纪律 / 按群策略段），
还特意做了"跨轮不变的前插、逐轮变的留末尾"来保护前缀缓存。

讽刺的是：**`hooks` 本来就是这个函数的入参**（`lintKindPlacement(kind, { manifest, toolIds, providers, hooks, promptSections })`，
第 684 行还拿它算过 `provides`），只是没拿它判断"有没有引导"。所以这是**遗漏**，不是设计。

### 为什么不用"补一段 prompt.sections"来消警告

那会和钩子里的 5 段**重复注入**。跑团群一轮带 26K 剧本/规则，前缀缓存对重复段最敏感 ——
消一个假警告的代价是每轮多付一笔钱，纯亏。

## 二、做法：声明式出口 `toolGuidance`

`skill.json` 加一行：

```json
"toolGuidance": "hooks"
```

含义："工具引导写在 hooks 里（典型就是 `before-llm-messages`），别提示我。"
lint 判据加 `&& !manifest.toolGuidance`。

**关键一点（这次踩到的坑）**：`normalizeManifest()` 是**白名单**，
不在返回对象里显式列出的字段**一律丢弃** —— 光在 `skill.json` 里写 `toolGuidance` 是无效的，
必须同时在 `src\skills\manifest.js` 的白名单里放行。所以这次的补丁是 **3 处**：

| # | 文件 | 改法 |
|---|---|---|
| 9 | `src/skills/manifest.js` | `prompt: normalizePrompt(raw.prompt),` 之后插入 `toolGuidance: cleanString(raw.toolGuidance, ''),` |
| 10 | `src/plugin-loader.js` | 在 lint 那段上方补注释（说明出口怎么用），纯注释零风险 |
| 11 | `src/plugin-loader.js` | **替换**判据那一行：末尾加 `&& !manifest.toolGuidance` |

核心补丁从 **8 件变 11 件**（copy 5 + anchor-insert 5 + replace-line 1）。
新增的 3 件**手拷做不到**，手动版见 `核心补丁\toolGuidance-手动接线.md`。

## 三、顺带给 `apply-core-patch.ps1` 加了 `replace-line`

```json
{ "kind": "replace-line", "from": "<整行原文>", "to": "<替换后的整行>", "marker": "<已打过的痕迹>" }
```

三条纪律：

1. **幂等**：文件里已含 `marker` 就跳过；
2. **必须命中且只命中一处**：命中 0 处 → 报错"宿主版本不同，请手动改"；命中多处 → 报错并**不动手**
   （宁可不动，也不猜要改哪一行）；
3. 替换前照样备份。

这条能力是后面两件事的前置：`reply-rescue.js` 有一处是"单行替换"（`messages` → `guarded`），
`prompt.js` 转锚点时也会用到。

## 五、边界：为什么 kp 的"没引导"在某种情况下确实成立

kp 的钩子第一行是 `if (!binding) return;` —— **群没绑定团本时零注入**。
那种群里 `kp__*` 工具仍在工具表里却没有引导。不过那时调用返回的是
「本群还没有绑定团本」，本来就是错误路径，可接受；真要收紧，应该在 `isActive()` 层面
按群隐藏工具，而不是靠这段提示词。

## 六、升级注意

- 改的两个核心文件是 `src\skills\manifest.js` 与 `src\plugin-loader.js`，**必须重启**；
- `skills\kp\skill.json` 加了 `"toolGuidance": "hooks"` —— **kp 不在分发包里**（本包只带 5 个技能），
  所以这条只影响你这台机器；给别人装的机器上，只要他的 kp 也加这一行就能同样消警告（核心补丁 9~11 是通用的）。
- 数据零影响（没有任何存档格式变化）。
