## 一、新组件（4 个）

### 庭院总线 `plugins\courtyard-bus`（★ 事件总线试点）

- 组件间**进程内事件 Pub/Sub**：`publish / subscribe` 实时事件，替代"写自己的 JSON、
  定时去读别人的 JSON"的轮询延迟（v1 架构最长 10 分钟）
- 当前已通一条链：sleep-mood 情绪位移 → mind-wish **即时吸收**（去抖 30 秒）
- **零依赖、零 fs、重启即清**——总线挂了各组件自动退回轮询，功能不受损（降级红线）

### 自传体记忆 `plugins\autobiography`（★ L3 长期记忆）

- **每晚 23:30 巩固**：把当天流水（庭院活动/明信片/B站日记/情绪波动/好感变化）
  提炼成 1~3 条"她自己的回忆"节点，存 `data\autobiography\nodes.json`
- **白天召回注入**：最近 3 条 + 故地重游优先（提示词片段带 `volatile` 声明，
  宿主自动沉到 user 尾部，不破坏前缀缓存）
- LLM 提炼失败自动走模板兜底；凭据一律不入库
- **依赖**：只读 travel-whale / bili-whale / sleep-mood / favor-core 的数据

### 知识库 `plugins\knowledge-base`

- 把 txt / md 丢进 `data\knowledge-base\`，机器人回答前先翻本地知识库，
  翻不到才上网搜，搜到的自动存进 learned/ 子目录
- v1.1 起每条记录带元数据（topic / weight 1~5），同主题合并、重要度参与排序

### 学习与反馈闭环 `plugins\learning-loop`

- **常态化自主学习**：每轮扫描消息识别纠正/确认/「记一下」信号；
  知识库与记忆检索无命中时把查询记成待学条目
- **共识入库**：≥2 个不同信源说过、或同一人 ≥2 个不同日期重复说过、
  或主人明确要求记——满足任一即自动写进知识库 learned/

> 这两个是**一对**：learning-loop 产出进 knowledge-base，一起装、一起开。

## 二、Persona Pack 第一阶段（角色名册数据化）

- 旅伴名册从 `state.js` 硬编码抽成 **`skills\travel-whale\persona\companions.json`**：
  想养别的角色（赛博猫娘/魔法学院魔女/废土机械师），改这一个 JSON 就行——
  字段：id / name / emoji / price / 倍率 / aliases / 特色开关
- 文件缺失/损坏/校验不过 → 自动回退内置名册，行为与 v2.0.0 逐字节一致
- 默认文件 = 当前"小鲸鱼"名册的原样导出（7 位旅伴）

## 三、提示词与发送链路标准化（§3 蓝图落地）

### 出站守卫管道（§3.3）

- `reply-rescue.js` 新增 `registerOutboundGuard(fn)`：插件可注册自定义出站审查器，
  在救援网产出**最终句子之后**逐个执行——返回 null 否决整轮、返回 messages 收窄、
  抛错不影响链路
- 注册途径：`api.services().registerOutboundGuard(fn)`

### sendProactive 统一（§3.1 收尾）

- 宿主 services 新增标准主动发送入口：限频/去重/留档全走核心发送队列
- `silence-ping` 发送链升级为四层：**核心队列（新，首选）** → affinity/chat 能力 →
  OneBot HTTP（SnowLuma 令牌发现保留为降级）→ 静默
- `bili-whale` 通知通道补全：`initNotify` 直接从 services 接住 sender，
  进程刚起、还没收到消息时的通知也能走核心管道（不必等第一条消息）

### 提示词段 volatility 声明（§3.2）

- 宿主已支持片段级 `volatile: true` 声明（声明式沉底，不破坏前缀缓存）；
  自传体记忆的召回片段是第一个使用者
