# 更新日志 · V2.2.7（2026-10-26）

> **热修版**：只修两个会让「面板整页空白」的缺陷，功能与数据格式不动。
> 组件版本：`courtyard-map` 1.1.0 → **1.1.1**；`travel-whale` 保持 4.4.6。
> 另：官方 0.4 宿主需要**同步升级适配补丁到 v1.1.2**（见第六节），否则面板仍拿不到数据。

## 一、`portraitExists is not defined` —— 面板整页空白（作者的锅）

### 现象

```
ReferenceError: portraitExists is not defined
```
出现在任何宿主、任何配置下，只要 `publishNow()` 跑一次（启动 30 秒内必跑）：
快照不生成 → `@data/storage.json` 没有 → 面板打开是空的。

### 根因

v2.2.6 打包时我把立绘探测函数从

```js
function portraitExists(id) { … }                  // 返回 true/false
```

改成了支持多扩展名的

```js
function portraitOf(id) { … }                      // 返回 'portraits/<id>.webp'
```

但**调用点没跟着改**，仍然是：

```js
portrait: portraitExists(id) ? `portraits/${id}.png` : '',
```

于是「定义了 A、调用了 B」。`node --check` 抓不到（这是运行时 ReferenceError），
`verify-load.mjs` 也抓不到（加载阶段不跑 `publishNow`）—— 所以漏到了下游。

### 修复

调用点改为 `portrait: portraitOf(id),`，与函数定义一致。
顺手把**现役宿主**（0.4.8.x）也统一成同一份实现，避免以后再次「打包时从现役取代码、两边的函数名又对不上」。

### 验证

- `node --check` 通过；
- 装载 27 个组件后触发快照，`portrait` 字段取到 `portraits/<id>.webp`（本包内立绘是 webp）；
- 立绘缺失时 `portraitOf()` 返回 `''`，面板回退 emoji 图标，不报错。

## 二、`api.storage` 不存在 —— 快照无处落地（作者与适配层各一半）

### 现象

面板打开了，但里面一行数据都没有；`/plugin-panel/courtyard-map/@data/storage.json` **404**。

### 根因（两段）

1. **作者侧**：`courtyard-map` 按「宿主有 `api.storage`」来写（`publishNow` 里 `api.storage.set('view', snap)`）。
   0.4.8.x 确实有；但**官方 0.4 preview 的 `createSkillApi` 没有 `storage`**。
2. **适配层侧**：官方 0.4 适配补丁 v1.1.0 / v1.1.1 只补了**面板路由**（`/plugin-panel/…` 与 `@data` 映射），
   **没补写入端**。路由读的是 `<DATA_DIR>/plugin-data/<id>/storage.json`，可没人往那儿写 → 永远 404。

因为调用处写的是 `api?.storage?.set?.(…)`（可选链），所以**不报错、只是静默不写** —— 最难查的那种。

### 修复

| 侧 | 动作 |
|---|---|
| 适配层 v1.1.2 | 给 `src/plugin-loader.js` 补 `makeSkillStorage(skillId)` 与 `api.storage`（`{get,set,remove}`），落盘路径与面板路由同源：`<DATA_DIR>/plugin-data/<id>/storage.json`；带 1MB 上限与 `__proto__` 防护（照 0.4.8.x 原样移植） |
| 完整包 v2.2.7 | 不依赖「有没有 storage」这一点不变（可选链保留），但**必须配合适配层 v1.1.2** 才能看到数据 |

> 用 0.4.8.x 宿主的人不受影响（那边本来就有 `api.storage`）。

### 验证（0.4 preview 实机）

```
api 有 storage: true | set/get/remove: function/function/function
写入 7 条 → 回读 7 条 ✅
落盘：<DATA>/plugin-data/courtyard-map/storage.json，键 view，view.companions 7 条 ✅
__proto__ 防护：✅ 拦截   1MB 上限：✅ 拦截   remove → get 返回 null ✅
再跑 verify-load：27/27 成功 0 失败
再跑 verify-panel：面板路由 / assets / api-skills 全 200
```

## 三、升级注意

1. 覆盖 `skills/courtyard-map`（1.1.1）即可，**不需要**动 `travel-whale`、插件、数据。
2. **官方 0.4 宿主**：务必同时把适配补丁升到 **v1.1.2**（多 3 条：`DATA_DIR` 导入、`makeSkillStorage`、`api.storage` 成员）。
3. 0.4.8.x 宿主：只覆盖 courtyard-map 就行，适配补丁与你无关。
4. 重启后 30 秒内面板就该有数据；若仍空白，先看 `data/plugin-data/courtyard-map/storage.json` 有没有生成。

## 四、这两个 bug 为什么没被自己的验证拦住（改进）

| 验证 | 能抓 | 抓不到 |
|---|---|---|
| `node --check` | 语法错 | 运行时 ReferenceError |
| `verify-load.mjs` | 组件加载失败 | `publishNow` 这类**运行期**路径 |
| `verify-panel.mjs` | 路由 404 / manifest 缺字段 | 路由通、但**文件不存在**（正是本次症状） |

补救（已加进本次验证）：装载后**主动触发一次快照**，断言 `storage.json` 真的生成，
并断言 `api.storage` 的 `set/get/remove` 与两条防护可用。
