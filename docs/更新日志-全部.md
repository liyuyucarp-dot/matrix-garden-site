## v3.2.3 · P6 收尾：旅行播报也进限流

> 2026-10-28 ｜ 包版本 `3.2.3` ｜ 只改 travel-whale 的发送入口，不动工具回话路径

### 为什么不能"全都限"

`say()` / `sayImage()` 被两类调用共用：

| 调用方 | 性质 | 该不该限 |
|---|---|---|
| `tools-core.js` / `tools-more.js`（模型响应群友时发面板/图） | **回话** | ❌ 限了她会"该说话时闭嘴" |
| `ticker.js` / `postcards-settle.js` / `side-trips.js` / `companions-voice.js`（后台自己说话） | **自主播报** | ✅ 该限 |

所以加了显式入口 `sayP()` / `sayImageP()`（= `say(..., { proactive: true })`），
只把这 4 个后台文件的 15 处调用换过去（9 + 5 + 3 + 1），**工具侧一行没动**。

### 接线

`proactiveGate(chatKey)` → `globalThis.__courtyardInfra.limiter.take({ chatKey, proactive: true })`
- 拿不到限流器（组件单独安装）→ 放行
- 限流器自身抛错 → 放行
- 被拒 → 打一行日志并返回 `false`（这条播报不发，下轮还有机会）

### 闸4d 新增契约断言（防绕过）

- `broadcast.js` 必须导出 `sayP` / `sayImageP`，且 `say`/`sayImage` 里有 `proactiveGate` 调用
- 上述 4 个后台文件里**不许再出现裸 `say(`** —— 否则就是绕限流的漏口

### 覆盖率盘点（P6 三个源头）

| 源头 | 状态 |
|---|---|
| silence-ping 主动私信 | ✅ v3.2.1 接入 |
| travel-whale 明信片 / 出发到家 / 旅伴自游播报 | ✅ 本次接入 |
| qzone 主动互动 | **不存在**：它的轮询只读（"静默、不主动发消息"），发说说/评论全是模型响应工具调用 → 不该限 |

## v3.2.2 · P5：状态原语接入（先审计，只改该改的）

> 2026-10-28 ｜ 包版本 `3.2.2` ｜ `courtyard-bus 0.2.0 → 0.2.1`（新增 `readText` / `writeText`）

### 先审计，再动手

原计划"剩下 12 个组件全迁"。实测审计后发现**大部分不需要**（它们各自已有原子写和 mtime 读缓存）：

| 文件 | 写点 | 原子写 | 读缓存 | 处置 |
|---|---:|---|---|---|
| sleep-mood/lib/mood-chain | 1 | ✓ | ✓ | **不动**（自己就有 `_cache` + tmp+rename） |
| silence-ping | 3 | ✓ | ✓ | **不动**（`stateCache` + 4 次重试 + `.broken` 自愈） |
| qzone/lib/diary | 3 | ✓ | ✓ | **不动** |
| knowledge-base | 2 | ✓ | ✓ | **不动** |
| learning-loop | 6 | ✓ | ✓ | **不动**（append 已在 v3.2.0 迁过） |
| **sleep-mood/lib/her-ledger** | 1 | **✗ 裸写** | ✗ | ✅ 迁（崩在半行就是坏账本） |
| **sleep-mood/lib/travel-sync** | 1 | **✗ 裸写** | ✗ | ✅ 迁 |
| **sleep-mood/lib/self-state** | 1 | ✓ | ✗ | ✅ 迁（每轮都读，缓存收益大） |
| **qzone/lib/social** | 2 | ✓ | ✗ | ✅ 迁（统一原子写 + 读缓存） |
| **travel-whale/state** | 1 | ✓ | ✗ | ✅ **只加读缓存，写入路径一动不动** |

⇒ 净改动 **5 个文件、8 处**，而不是 12 个组件 40 处。**审计省下的不是工作量，是回归面积。**

### 新增能力

`courtyard.store` 加两个同步 API：
- `readText(file)` —— 每次只 `stat` 比对 mtime，没变直接给缓存（省掉 `readFileSync` + `JSON.parse`）。**故意不设 60s 复核窗口**：存档级文件读旧值会被写回去覆盖新数据，多一次 stat（≈0.05ms）换绝对正确。
- `writeText(file, text)` —— 原子写（tmp→fsync→rename）+ 立刻更新缓存，与"自己手写 tmp+rename"语义一致，只是不再各写一遍。

组件侧统一两个本地 helper（`readTextCached` / `writeTextCached`），**拿不到 store 时逐字退回原来的 fs 写法**。

闸4d 新增 4 条断言：写后读不回原值 / 连续读必须命中缓存 / 外部改动后必须看到新值 / `writeText` 不残留 tmp。

⚠️ 拿不到限流器时**一律放行**（基础设施只能更克制，不能让功能消失）；限流器自身抛错也放行。

## v3.2.0 · 状态总线落地 + 提示词量化（P0→P3→P1）

> 2026-10-28 ｜ 包版本 `3.2.0` ｜ 组件 `courtyard-bus 0.1.0 → 0.2.0`

**先纠两个前提**（实测，不是估算）：

| 原计划 | 实测结论 | 处置 |
|---|---|---|
| P0 加缓存统计 | 宿主**已有** `[cache-stat]` 日志（每轮 `prompt= / cached= / %`） | 不写统计代码，改为做**报表工具** `tools/cache-report.mjs` |
| P3 给动态 section 标 volatile | 实测命中率 **90.0%**（3 天加权 95.4% / 92.2% / 86.2%），system 形状变化仅 264 次/天 | **跳过**（改了反而把规则挪出 system） |

**实测基线**（`node tools/cache-report.mjs --dir <logs>`）：

```
日志          调用    prompt    cached    命中率   形状变化
2026-10-28     699   26572k    25340k     95.4%      135
2026-10-27    1491   64201k    59218k     92.2%      261
2026-10-26    1873   76231k    65738k     86.2%      396
合计          4063  167004k   150296k     90.0%      792
→ 每轮平均 miss ≈ 4k token（= user 提示词 + 尾部注入），不是命中率问题
```

**P1 落地：courtyard-bus 0.2.0 = 四个同级能力**

| capability | 能力 |
|---|---|
| `courtyard.bus` | 原有进程内 Pub/Sub（**仍是零 fs**，不动） |
| `courtyard.store` | StateStore：读缓存 + **按文件**排队 + write-temp-rename 原子写 + 3s 防抖合并；`update(file, fn)` 在锁内算，杜绝并发读-改-写互相覆盖 |
| `courtyard.clock` | 中央心跳：一个 1s 主循环 + 最小堆到期队列 + ±15% 抖动错峰 + 单任务 30s 超时 + 连续失败自动降频 |
| `courtyard.limit` | 令牌桶限流：全局 30/10min、单会话 8/10min、主动消息 3/h；**只拦主动消息，回应用户不占桶** |

全部**可选**：拿不到 capability 的组件保持原有直读直写。新增**闸4d** `tools/probes/statebus.mjs` 覆盖：并发 20 次 +1 不丢、50 行追加不丢、无残留 tmp、外部改动可见、定时器可注销且坏任务隔离、限流额度正确。

**首批迁移：learning-loop**（4 处 `appendFileSync` → 原子追加；ledger 的"追加+超限裁剪"合并进同一把锁内 —— 原来两者分开，并发时裁剪会把刚写的行裁掉）

**提示词量化**

- **好感**：注入文本 `好感73/100·亲` → **`好感·亲`**（只给档位）。理由：精确值每变 1 点就换文本、且模型容易把数字复述进群（"我对你 73 分"）。需要精确值时走 `memory_favor` 工具照旧返回 `好感73/100`。
- **元气**：`mood-chain.js` 本来就有 `bandOf()`（10 档），无需改。

**踩坑**：写迁移脚本时把 `let apiRef` 又声明了一遍（文件里本来就有）→ 加载闸报 `Identifier 'apiRef' has already been declared`。教训：**改别人文件前先 grep 一遍要引入的标识符**。

## v3.1.1 · 工具描述瘦身（常驻成本 -11.6%）

> 2026-10-28 ｜ 包版本 `3.1.1` ｜ 纯文案瘦身，**接口与行为不变**，重启即生效

**背景**：工具描述是**每轮都随 tools 段发出去**的固定成本，而且 tools 段在 messages 之前 ——
它一变就打穿前缀缓存。之前这些描述里混进了大量"给开发者看的实测教训"（"★☆ 2026-10-14 用户报……"
"实测今天一整天只被调到 1 次"），模型用不到，但每轮都在付钱。

**做法**：只保留「做什么 / 何时用 / 必填参数填什么 / 硬约束」，把源码注释性质的教训移回提交说明。

| 组件 | 改前字符 | 改后字符 | 省 |
|---|---:|---:|---:|
| travel-whale | 9,291 | 8,324 | 967 |
| knowledge-base | 3,405 | 2,731 | 674 |
| qzone | 3,267 | 2,950 | 317 |
| **合计** | **19,690** | **17,411** | **2,279** |

≈ **12,208 → 10,795 token/轮**（-11.6%）。18 个工具被改，改动最大的是
`kb_remember`(-379 字符)、`whale_go`(-275)、`kb_update`(-185)、`whale_buy`(-184)、`whale_help`(-176)。

**新增闸7（工具段预算）**：`tools/probes/toolcost.mjs`
- 单工具 desc+params > 1,050 字符 → 失败
- 单工具 description > 300 字符 → 失败
- 全量合计 > 19,200 字符 → 失败；`travel-whale` 单独卡 8,800
- 口径用**字面量拼接**（不用运行时抓 registerTool：桩环境里 setup 会早退，抓不全）

**踩过的坑（写下来防复发）**：
- 第一版瘦身脚本用 `new.rstrip(", \n")` 把描述末尾的逗号也削掉了，导致 3 个组件
  （travel-whale / knowledge-base / courtyard-map 连带）`import` 时报 `Unexpected identifier 'parameters'`。
- 更糟的是我当时用 `node --check ... | Select-Object` 校验，**读到的退出码是管道的**，
  显示"ok"其实已经失败 —— 是闸3b 抓出来的。**校验语法永远别把输出接管道再取退出码**。
